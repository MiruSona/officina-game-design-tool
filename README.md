# GamedesignTool — 기획 단계 관문과 대시보드

**지금 기획이 몇 단계인지 지키게 막고(`stage`), 그 상태를 정적 HTML 한 장으로 구워 보여 주는(`dash`) 툴이다.**

단일 실행 파일 하나. 상주 프로세스도 서버도 없다. LLM 을 부르지 않는다.

## 왜 있나

기획 절차는 **1~9단계**를 돌고, 3~6단계가 되풀이되는 고리다.
그런데 **규칙 문서에 적어 두는 것만으로는 지켜지지 않는다.** 훅으로 막아야 실제로 지켜진다.

원칙은 하나다. **훅은 모양을 검사하고, 판단은 사람이 한다.**
「재미있나」는 훅이 못 본다. 「기둥이 3~4개인가」 같은 **셀 수 있는 것만** 본다.
그리고 **단계를 넘기는 것은 사용자만 한다** — 툴은 상태 파일을 읽어 막기만 한다.

## 게임 저장소와의 경계

**이 저장소에는 게임 낱말이 하나도 안 들어간다.** 어느 게임에 붙여도 그대로 돌아야 한다.

| 여기(GamedesignTool) | 게임 저장소 |
| --- | --- |
| 단계 정의 **기본값**(9단계) · 검사 규칙 · HTML 템플릿 · 훅 스크립트 | **상태 파일** `Docs/Todo/기획상태.json` |
| **절차 정본** `Docs/Guide/기획절차.md` | 기획 문서 · 물음과 판정 기준 · 프로토타입 · 기억 |
| 툴 자신의 조사·설계·할 일 문서 | 판정 기록 · 공수 기록 |

**단계 정의는 툴이 기본값을 갖고, 게임 저장소의 설정 파일로 덮어쓴다.**
게임마다 단계 수와 이름이 다를 수 있으니 툴에 못 박지 않는다.

## 두 몫

### ① 단계 관문 CLI (`stage`)

| 명령 | 하는 일 |
| --- | --- |
| `stage init` | 상태 파일을 1단계 · 1판으로 새로 만든다 |
| `stage show` | 지금 단계 · 판 번호 · 이번 판 물음 상태를 글로 (`--json` · `--hook`) |
| `stage next` | 다음 단계로. **사용자만 한다** — 기준을 되뇌기만 하고 막지 않는다 |
| `stage back <단계> --why "…"` | 되돌아간다. **되돌아간 기록을 남긴다** — 몇 판 돌았는지를 여기서 센다 |
| `stage ask "<물음>" --crit "…"` | 이번 판 물음과 판정 기준을 적는다 |
| `stage check <물음id> pass\|fail --note "…"` | 검증 단계의 통과/불통을 적는다 |
| `stage lint [<파일…>]` | 훅이 부르는 **모양 검사** — 문서 순서 · 기둥 개수 · 필수 칸이 비었나 · 파일 이름 규칙 |
| `stage done` | 판 끝 할 일이 빠졌는지 본다 (경고만) |
| `stage dash` | 아래 ②. 정적 HTML 한 장을 굽는다 |

**옵션은 명령 뒤에 둔다** — `stage show --root C:\어디\저장소`.
종료 코드는 0 잘 됨 · 1 쓰는 법 · **2 검사에 걸림** · 3 읽기 실패 · 4 쓰기 실패 · 5 파일 깨짐이다.

**상태 파일**은 게임 저장소의 `Docs/Todo/기획상태.json` 하나다 (30줄쯤).
단계 · 판 번호 · 되돌아간 기록 · 프로토타입 배열(물음 / 상태 / 기준)이 들어간다.
**정본은 이 파일이다.** 툴은 이걸 읽고 쓰기만 한다.

**훅 셋** — 게임 저장소의 `.claude/settings.json` 에 건다.

| 훅 | 언제 | 부르는 것 | 어떻게 |
| --- | --- | --- | --- |
| `SessionStart` | 세션을 열 때 | `stage show --hook` | 종료 0 + stdout 이 문맥에 들어간다. 상태 파일이 없어도 안 죽는다 |
| `PreToolUse` (Write\|Edit) | 문서·코드를 쓰기 직전 | `stage lint --hook` | stdin 으로 훅 JSON 을 받는다. 막을 때 **종료 2 + stderr 에 까닭** |
| `Stop` | 한 판이 끝날 때 | `stage done --hook` | 빠진 것이 있으면 `{"systemMessage": "…"}` 한 줄. **막지 않는다** |

훅 조각은 붙은 저장소의 `.claude/settings.json` 에 넣는다. 자세한 꼴은 설계 문서 5장.
**`bin/` 은 gitignore 라 받은 직후에는 exe 가 없다** — 그때 훅은 그냥 실패하고 아무것도 막지 않으니
받으면 먼저 아래 「빌드」를 한 번 친다.

**프로토타입 폴더는 검사에서 뺀다.** 버릴 코드를 훅이 막으면 아무도 프로토타입을 안 만들게 된다.

### ② 대시보드 (`dash`)

정적 HTML **한 장**을 굽는다. 서버가 없다. 더블클릭하면 열린다.
**보기 전용이다** — 웹에서 고치지 않는다. 사람이 말하면 AI 가 파일을 고친다.

| 탭 | 무엇이 보이나 | 언제 |
| --- | --- | --- |
| **상태** | 9단계 스테퍼(지난 단계 채움 · 지금 강조 · 앞은 흐리게) · 지표 타일 3개(되돌아간 횟수 / 물음 통과 수 / 예상 대비 실제 공수) · 기둥 상자 · 문서 뼈대 체크 · 되돌아가는 고리 상태도 | **1판** |
| **프로토타입 갤러리** | 열 4개 칸반(만드는 중 · 확인 대기 · 통과 · 불통). 카드에 물음 한 줄 + 판정 기준 개수 | 2판 |
| **밸런스** | 수치 표 · 곡선 그래프 · 식을 글자 그대로 보여 주기 · 읽기 전용 미리보기 슬라이더 | 나중 (세로 조각 단계) |

- **한 화면의 덩어리는 여섯을 넘기지 않는다.** 일곱부터는 아무도 안 본다.
- 갤러리 탭은 **프로토타입 툴이 만든 `proto-meta` 를 읽기만 한다.** 고치지 않고, 코드로 묶지도 않는다.
  형식이 바뀌면 문서로 맞춘다.
- 밸런스 탭은 **실제 수치가 생긴 뒤에** 만든다. 상상으로 만든 툴은 다 틀린다.
- 슬라이더는 **브라우저 안에서만** 값을 흔든다. 파일을 안 건드리니 AI 편집과 부딪히지 않는다.

## 폴더 구조

```
README.md · LICENSE · .gitignore · go.mod
.claude/skills/gamedesign-usage/SKILL.md   ← 쓰는 법
cmd/stage/           ← 명령 갈래 · 옵션 · 종료 코드만
internal/
  config/   단계 9칸 기본값 + 설정 파일로 덮기
  state/    상태 파일 읽고 쓰기 · 판 번호와 되돌아간 기록 규칙
  mdscan/   마크다운에서 표를 세기 (기둥 · Won't · 줄 수)
  lint/     검사 규칙 L1~L8
  hookio/   훅 stdin JSON 읽기 · systemMessage 만들기 · 고침 적용 결과
  dash/     HTML 한 장 굽기
  paths/    뿌리 · 상대 경로 · 검사에서 뺄 자리
  render/   터미널 글 폭 맞추기 (한글 두 칸)
templates/dash.html  ← embed 로 실행 파일 안에 들어간다
testdata/            ← 예시 저장소 둘(repo-ok · repo-bad) + 훅 JSON 셋
Docs/
  Guide/기획절차.md  ← 절차 정본 (아래)
  Design/     ← 설계 문서 (1판 설계 : 2026-09-07-1판설계.md)
  Research/   ← 조사 문서
  Todo/할일.md ← 만들 것 차례
```

## 빌드

```powershell
$env:CGO_ENABLED="0"
go build -o bin/stage.exe ./cmd/stage
```

GamedesignTool 폴더 안에서 친다. 스튜디오(Officina) 저장소에서라면 `cd GamedesignTool` 을 먼저 한다.
**`bin/` 은 git 에 안 올라간다** — 받은 직후에 한 번 친다. 안 치면 훅이 조용히 아무것도 안 막는다.

### `Docs/Guide/기획절차.md`

**옮겨 왔다 (2026-09-06). 절차 정본이다.** 9단계 · 되돌아가는 조건 · 판 규칙 · 훅 표가 여기 있다.
게임 낱말과 게임 저장소 경로는 뺐다. 절차만 남겼다.

붙은 게임 저장소는 이 파일을 가리키고 **자기 게임의 확정 값만** 따로 둔다. 절차를 두 벌로 적지 않는다.

## 어디서 부르나 — 명령 두 벌

| 어디서 쓰나 | 명령 앞자리 |
| --- | --- |
| 스튜디오(Officina) 저장소에서 | `.\GamedesignTool\bin\stage.exe …` |
| 게임 저장소에서 (서브모듈) | `.\Tools\GamedesignTool\bin\stage.exe …` |
| GamedesignTool 저장소 단독에서 | `.\bin\stage.exe …` |

문서와 스킬의 예시는 **짧은 쪽**(`stage …`)으로 적는다. 실제로 칠 때 위 앞자리를 붙인다.

## 붙은 저장소가 지켜야 할 마크다운 규약

훅이 세려면 **어디를 세는지가 못 박혀** 있어야 한다. 기획 문서는 아래 모양으로 쓴다.

| 무엇 | 어디를 보나 | 세는 법 |
| --- | --- | --- |
| 기둥 개수 | `00-컨셉.md` 의 `## 기둥` 제목 (뒤에 글자가 더 붙어도 된다) | 그 제목부터 **다음 `##` 전까지**의 **첫 표**의 본문 줄 수 (머리줄·구분줄은 안 센다) |
| Won't 칸 | `02-기능목록.md` 의 **첫 표** | 첫 칸이 `Won't` 인 본문 줄 수 (굵게 표시는 떼고 본다) |
| 파일 이름 | 기획문서폴더 **바로 아래**의 `.md` | `NN-이름.md` 꼴. **하위 폴더는 검사 밖** |

## 만드는 차례

1. ~~상태 파일 모양 정하기~~ — 끝. 칸 이름은 설계 문서 1장.
2. ~~`stage show` · `next` · `back` · `check` (+ `init` · `ask`)~~ — 끝.
3. ~~`stage lint` + 훅 셋~~ — 끝. 훅은 붙은 저장소에 걸어야 실제로 돈다.
4. ~~`dash` 상태 탭~~ — 끝. 여기까지가 1판.
5. 갤러리 탭(2판) → 밸런스 탭(나중).

**툴에 총 3일을 넘겨 쓰지 않는다.** 3일에 안 끝나면 설계가 큰 것이다.
툴 만들기가 게임 만들기를 잡아먹는 것은 잘 알려진 함정이다.

## 공개 저장소 검사

이 저장소는 공개다. 비밀값·개인정보·게임 낱말·남의 툴 이름이 들어가지 않게 `.claude/hooks/public_guard.py` 가 막는다.
받은 직후 한 번 `python .claude/hooks/public_guard.py --install` 을 친다 (git pre-commit 훅). 자세한 것은 `.claude/hooks/README.md`.

## 규칙

작업 규칙(`AGENTS.md` · `CLAUDE.md`)은 **이 저장소에 두지 않는다.**
스튜디오(Officina) 저장소나 붙어 있는 게임 저장소의 것을 따른다.
문서 문체와 자리 규칙도 그쪽 `doc-writing` 스킬을 본다.
