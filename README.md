# GamedesignTool — 기획 단계 관문과 대시보드

**지금 기획이 몇 단계인지 지키게 막고(`stage`), 그 상태를 정적 HTML 한 장으로 구워 보여 주는(`dash`) 툴이다.**

단일 실행 파일 하나. 상주 프로세스도 서버도 없다. LLM 을 부르지 않는다.

## 왜 있나

기획 절차는 **1~9단계**를 돌고, 3~6단계가 되풀이되는 고리다.
그런데 **규칙 문서에 적어 두는 것만으로는 지켜지지 않는다.** 훅으로 막아야 실제로 지켜진다.

원칙은 하나다. **훅은 모양을 검사하고, 판단은 사람이 한다.**
「재미있나」는 훅이 못 본다. 「기둥이 3~4개인가」 같은 **셀 수 있는 것만** 본다.
그리고 **단계를 넘기는 것은 사용자만 한다** — 툴은 상태 파일을 읽어 막기만 한다.

## 게임 저장소와의 경계

**이 저장소에는 게임 낱말이 하나도 안 들어간다.** 어느 게임에 붙여도 그대로 돌아야 한다.

| 여기(GamedesignTool) | 게임 저장소 |
| --- | --- |
| 단계 정의 **기본값**(9단계) · 검사 규칙 · HTML 템플릿 · 훅 스크립트 | **상태 파일** `Docs/Todo/기획상태.json` |
| 절차 문서(아래 「기획절차.md 자리」) | 기획 문서 · 물음과 판정 기준 · 프로토타입 · mem |
| 툴 자신의 조사·설계·할 일 문서 | 판정 기록 · 공수 기록 |

**단계 정의는 툴이 기본값을 갖고, 게임 저장소의 설정 파일로 덮어쓴다.**
게임마다 단계 수와 이름이 다를 수 있으니 툴에 못 박지 않는다.

## 두 몫

### ① 단계 관문 CLI (`stage`)

| 명령 | 하는 일 |
| --- | --- |
| `stage show` | 지금 단계 · 판 번호 · 이번 판 물음 상태를 글로 |
| `stage next` | 다음 단계로. **사용자만 한다** |
| `stage back <단계> --why "…"` | 되돌아간다. **되돌아간 기록을 남긴다** — 몇 판 돌았는지를 여기서 센다 |
| `stage check <물음> pass\|fail --note "…"` | 검증 단계의 통과/불통을 적는다 |
| `stage lint` | 훅이 부르는 **모양 검사** — 문서 순서 · 기둥 개수 · 필수 칸이 비었나 · 파일 이름 규칙 |
| `stage dash` | 아래 ②. 정적 HTML 한 장을 굽는다 |

**상태 파일**은 게임 저장소의 `Docs/Todo/기획상태.json` 하나다 (30줄쯤).
단계 · 판 번호 · 되돌아간 기록 · 프로토타입 배열(물음 / 상태 / 기준)이 들어간다.
**정본은 이 파일이다.** 툴은 이걸 읽고 쓰기만 한다.

**훅 셋** — 게임 저장소의 `.claude/settings.json` 에 건다.

| 훅 | 언제 | 무엇을 |
| --- | --- | --- |
| `SessionStart` | 세션을 열 때 | `stage show` — 지금 몇 단계이고 되돌아가는 조건이 무엇인지 문맥에 넣는다 |
| `PreToolUse` (Write/Edit) | 문서·코드를 쓰기 직전 | `stage lint` — 순서와 모양을 검사해 어긋나면 막는다 |
| `Stop` | 한 판이 끝날 때 | 판 끝에 할 일(기록 · mem · 진행상황 고치기)이 빠졌으면 경고한다 |

**프로토타입 폴더는 검사에서 뺀다.** 버릴 코드를 훅이 막으면 아무도 프로토타입을 안 만들게 된다.

### ② 대시보드 (`dash`)

정적 HTML **한 장**을 굽는다. 서버가 없다. 더블클릭하면 열린다.
**보기 전용이다** — 웹에서 고치지 않는다. 사람이 말하면 AI 가 파일을 고친다.

| 탭 | 무엇이 보이나 | 언제 |
| --- | --- | --- |
| **상태** | 9단계 스테퍼(지난 단계 채움 · 지금 강조 · 앞은 흐리게) · 지표 타일 3개(되돌아간 횟수 / 물음 통과 수 / 예상 대비 실제 공수) · 기둥 상자 · 문서 뼈대 체크 · 되돌아가는 고리 상태도 | **1판** |
| **프로토타입 갤러리** | 열 4개 칸반(만드는 중 · 확인 대기 · 통과 · 불통). 카드에 물음 한 줄 + 판정 기준 개수 | 2판 |
| **밸런스** | 수치 표 · 곡선 그래프 · 식을 글자 그대로 보여 주기 · 읽기 전용 미리보기 슬라이더 | 나중 (세로 조각 단계) |

- **한 화면의 덩어리는 여섯을 넘기지 않는다.** 일곱부터는 아무도 안 본다.
- 갤러리 탭은 **프로토타입 툴이 만든 `proto-meta` 를 읽기만 한다.** 고치지 않고, 코드로 묶지도 않는다.
  형식이 바뀌면 문서로 맞춘다.
- 밸런스 탭은 **실제 수치가 생긴 뒤에** 만든다. 상상으로 만든 툴은 다 틀린다.
- 슬라이더는 **브라우저 안에서만** 값을 흔든다. 파일을 안 건드리니 AI 편집과 부딪히지 않는다.

## 폴더 구조

```
README.md
LICENSE
.gitignore
.claude/skills/gamedesign-usage/SKILL.md   ← 쓰는 법 (지금은 뼈대)
Docs/
  Guide/      ← 기획절차.md 가 여기로 온다 (아래)
  Design/     ← 설계 문서
  Research/   ← 조사 문서
  Todo/할일.md ← 만들 것 차례
```

**앞으로 생길 자리** : `cmd/` · `internal/` · `templates/`(HTML 한 장 굽는 틀) · `hooks/`(훅 스크립트) · `testdata/`.

### `Docs/Guide/기획절차.md` 자리

**비워 두었다.** 절차 문서의 확정본이 지금 게임 저장소에서 편집 중이고,
**확정되면 다음 소단계에서 이리로 옮겨 온다.** 지금 복사하면 두 벌이 되어 반드시 어긋난다.

옮겨 올 때 게임 낱말과 게임 저장소 경로는 뺀다. 절차만 남긴다.

## 어디서 부르나 — 명령 두 벌

| 어디서 쓰나 | 명령 앞자리 |
| --- | --- |
| 스튜디오(Officina) 저장소에서 | `.\GamedesignTool\bin\stage.exe …` |
| 게임 저장소에서 (서브모듈) | `.\Tools\GamedesignTool\bin\stage.exe …` |
| GamedesignTool 저장소 단독에서 | `.\bin\stage.exe …` |

문서와 스킬의 예시는 **짧은 쪽**(`stage …`)으로 적는다. 실제로 칠 때 위 앞자리를 붙인다.

## 지금 상태

**뼈대만 있다.** 코드는 아직 하나도 없다. 1판에 무엇을 만드는지는 `Docs/Todo/할일.md` 를 본다.

## 만드는 차례

1. **상태 파일 모양 정하기** — 여기서 어긋나면 뒤가 다 어긋난다.
2. **`stage show` · `next` · `back` · `check`** — 상태 파일만 읽고 쓴다. 화면이 없어도 쓸 수 있다.
3. **`stage lint` + 훅 셋** — 막는 것은 CLI 가 서고 난 뒤에 붙인다.
4. **`dash` 상태 탭** — 여기까지가 1판.
5. 갤러리 탭(2판) → 밸런스 탭(나중).

**툴에 총 3일을 넘겨 쓰지 않는다.** 3일에 안 끝나면 설계가 큰 것이다.
툴 만들기가 게임 만들기를 잡아먹는 것은 잘 알려진 함정이다.

## 공개 저장소 검사

이 저장소는 공개다. 비밀값·개인정보·게임 낱말·남의 툴 이름이 들어가지 않게 `.claude/hooks/public_guard.py` 가 막는다.
받은 직후 한 번 `python .claude/hooks/public_guard.py --install` 을 친다 (git pre-commit 훅). 자세한 것은 `.claude/hooks/README.md`.

## 규칙

작업 규칙(`AGENTS.md` · `CLAUDE.md`)은 **이 저장소에 두지 않는다.**
스튜디오(Officina) 저장소나 붙어 있는 게임 저장소의 것을 따른다.
문서 문체와 자리 규칙도 그쪽 `doc-writing` 스킬을 본다.
