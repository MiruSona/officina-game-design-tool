# 1판 설계 — 관문 CLI(`stage`) 와 상태 한 장(`dash`)

> 대상 : `Docs/Todo/할일.md` 의 1판 부품 ①~⑤. **설계만** 적는다. 코드는 다음 판에 쓴다.
> 절차의 정본은 `Docs/Guide/기획절차.md` 다. 여기서는 절차를 다시 적지 않고 **자료형·명령·검사 규칙**만 정한다.

## 한 줄 요지

**상태는 붙은 저장소의 `Docs/Todo/기획상태.json` 한 개, 조절은 `stage` 명령, 보기는 `stage dash` 가 굽는 정적 HTML 한 장이다.**
툴은 셀 수 있는 것만 검사하고, 단계를 넘기는 것은 사용자만 한다.

## 만드는 것

| 무엇 | 자리 |
| --- | --- |
| 실행 파일 하나 | `bin/stage.exe` (`CGO_ENABLED=0`, 표준 라이브러리만) |
| 명령 진입점 | `cmd/stage/` |
| 속살 | `internal/<패키지>` 여덟 |
| HTML·CSS 틀 | `templates/` (`embed` 로 실행 파일 안에 넣는다) |
| 시험 재료 | `testdata/` |

모듈 이름은 `github.com/mirusona/officina-game-design-tool`.

## 1. 상태 파일 `Docs/Todo/기획상태.json`

**정본이다.** 툴은 읽고 쓰기만 한다. 사람이 손으로 고쳐도 되는 크기(30줄쯤)로 둔다.

### 칸

칸 이름은 한국어다. 물음 쪽 세 칸(`물음` · `기준` · `만든날`)은 **프로토타입 폴더의 `proto-meta` 와 같은 이름**을 쓴다.
나중에 갤러리 탭에서 둘을 겹쳐 볼 때 이름이 다르면 매번 옮겨 적어야 한다.

| 칸 | 자료형 | 뜻 |
| --- | --- | --- |
| `형식` | 정수 | 이 파일 모양의 판. 지금은 `1`. 모르는 값이면 툴이 멈춘다 |
| `단계` | 정수 1~9 | 지금 단계 |
| `판번호` | 정수 ≥ 1 | 3~6 고리를 몇 번째 돌고 있나 |
| `판시작일` | 문자열 `YYYY-MM-DD` | 이번 판이 시작한 날. 「이번 판 며칠째」의 밑값 |
| `고침시각` | 문자열 RFC3339 | 툴이 마지막으로 쓴 시각 |
| `물음` | 배열 | 아래 표 |
| `되돌아간기록` | 배열 | 아래 표 |

#### `물음[]`

| 칸 | 자료형 | 뜻 |
| --- | --- | --- |
| `id` | 문자열 | 짧은 손잡이. 영문·숫자·`-` 만. `stage check` 가 이걸로 찾는다 |
| `물음` | 문자열 | 한 문장. 하나만 물어본다 |
| `기준` | 문자열 배열 | 판정 기준 3~5줄. `proto-meta` 의 `기준` 과 같은 뜻 |
| `만든날` | 문자열 `YYYY-MM-DD` | 물음을 적은 날 |
| `판번호` | 정수 | 어느 판의 물음인가 |
| `상태` | `만드는중`·`대기`·`통과`·`불통` | 지금 상태 |
| `판정` | 배열 | `{ "언제": RFC3339, "값": "pass"\|"fail", "메모": "…" }` |

- **`상태` 는 `판정` 의 마지막 값에서 따라온다.** 두 곳에 적히지만 `판정` 이 정본이고 `상태` 는 뽑아 둔 값이다.
  `stage lint` 가 둘이 어긋났는지 본다.
- 프로토타입 파일 경로는 **넣지 않는다.** 폴더를 훑으면 알 수 있는 것을 상태 파일에 적으면 어긋난다. (2판 몫)

#### `되돌아간기록[]`

| 칸 | 자료형 | 뜻 |
| --- | --- | --- |
| `언제` | RFC3339 | |
| `어디서` | 정수 | 되돌아가기 직전 단계 |
| `어디로` | 정수 | 되돌아간 단계 |
| `판번호` | 정수 | 되돌아가기 **직전**의 판 번호 |
| `까닭` | 문자열 | `--why` 로 받는다. 비면 명령이 실패한다 |

### 예시 한 벌

```json
{
  "형식": 1,
  "단계": 6,
  "판번호": 2,
  "판시작일": "2026-09-07",
  "고침시각": "2026-09-07T21:10:00+09:00",
  "물음": [
    {
      "id": "start-slots",
      "물음": "시작 칸을 3칸으로 하는 게 맞나",
      "기준": ["5분 동안 멈추지 않고 돌렸다", "다음에 뭐 하지 하고 멈춘 횟수 2회 이하"],
      "만든날": "2026-09-07",
      "판번호": 2,
      "상태": "통과",
      "판정": [{ "언제": "2026-09-07T20:40:00+09:00", "값": "pass", "메모": "두 번 다 5분 넘김" }]
    },
    {
      "id": "wait-time",
      "물음": "기다리는 시간이 30초면 지루한가",
      "기준": ["멈춘 뒤 한 판 더 생각이 든다"],
      "만든날": "2026-09-07",
      "판번호": 2,
      "상태": "대기",
      "판정": []
    }
  ],
  "되돌아간기록": [
    { "언제": "2026-09-05T18:00:00+09:00", "어디서": 6, "어디로": 3, "판번호": 1, "까닭": "고리가 안 닫혔다" }
  ]
}
```

### 판 번호와 되돌아간 기록이 바뀌는 때

**규칙은 하나다 — 판 번호는 `back` 으로 3~6 안에서 되돌아갈 때만 오른다.**

| 명령 | 단계 | 판번호 | 판시작일 | 되돌아간기록 | 물음 |
| --- | --- | --- | --- | --- | --- |
| `next` (6 → 7 포함 어디서든) | +1 | 그대로 | 그대로 | 그대로 | 그대로 |
| `back 3\|4\|5` (3~6 고리 안) | 그 값 | **+1** | **오늘** | 한 줄 더함 | 그대로 (지난 판 물음은 `판번호` 로 갈린다) |
| `back 1\|2` (컨셉·기둥으로) | 그 값 | **1 로 되돌림** | **오늘** | 한 줄 더함 | 그대로 |
| `back 7\|8\|9` | — | — | — | — | **막는다.** 되돌아가는 것은 앞 단계로만 |
| `ask` | 그대로 | 그대로 | 그대로 | 그대로 | 한 줄 더함 (`판번호` = 지금 판) |
| `check` | 그대로 | 그대로 | 그대로 | 그대로 | 그 물음의 `상태`·`판정` |

- **「3판 돌아도 통과 못 하면 1~2단계로」** 는 이렇게 센다 : `판번호 ≥ 3` 이고 단계가 3~6 이면
  `show` 와 대시보드가 **「컨셉·기둥을 의심할 때다」** 를 띄운다. **막지는 않는다.** 판단은 사람이 한다.
- **「되돌아간 횟수」** 지표는 `되돌아간기록` 의 길이다. `back 1|2` 로 판을 되돌려도 기록은 안 지운다.

## 2. 설정 파일 `Docs/Todo/기획설정.json`

**없어도 된다.** 있으면 적힌 칸만 기본값을 덮는다 (얕은 덮기 — 배열은 통째로 갈아 끼운다).

| 칸 | 자료형 | 기본값 |
| --- | --- | --- |
| `단계` | 문자열 배열 | 아래 9칸 |
| `문서뼈대` | 문자열 배열 | `["00-컨셉.md", "01-코어루프.md", "02-기능목록.md", "03-시스템-*.md", "04-수치표.md", "05-진행과튜토리얼.md"]` |
| `기획문서폴더` | 문자열 | `Docs/Design` |
| `기둥개수` | `[최소, 최대]` | `[3, 4]` |
| `물음개수` | `[최소, 최대]` | `[2, 4]` |
| `컨셉줄상한` | 정수 | `60` (A4 반 쪽 눈금) |
| `프로토타입폴더` | 문자열 | `Prototypes` — **검사에서 뺀다** |
| `코드폴더` | 문자열 | `""` (빈 값 = 코드 순서 검사를 안 한다) |
| `고리단계` | `[시작, 끝]` | `[3, 6]` — 판 번호가 오르는 구간 |
| `판의심횟수` | 정수 | `3` |

기본 9단계 이름은 절차 정본 「큰 흐름」 표 그대로다.

| 번호 | 이름 |
| --- | --- |
| 1 | 컨셉 |
| 2 | 기둥 3~4개 |
| 3 | 코어 루프 |
| 4 | 물음 묶음과 판정 기준 |
| 5 | 거친 프로토타입 묶음 |
| 6 | 몰아서 검증 |
| 7 | 기능 자르기 |
| 8 | 세로 조각 |
| 9 | 확장 |

「끝났다고 보는 기준」 한 줄도 단계마다 코드에 같이 갖는다 (`next` 가 경고로 되뇐다). 설정으로 덮지 않는다 — 절차 정본의 값이다.

## 3. 명령

공통 옵션은 `--root <경로>` 하나다. **기본은 현재 폴더.** 훅은 저장소 뿌리에서 돌기 때문이다. git 을 부르지 않는다.

### 종료 코드

| 값 | 뜻 |
| --- | --- |
| 0 | 잘 됐다 |
| 1 | 쓰는 법이 틀렸다 (모르는 명령·모자란 인자·잘못된 옵션) |
| 2 | **검사에 걸렸다** — `lint` 가 막을 때. 훅이 이 값으로 도구 호출을 막는다 |
| 3 | 읽기 실패 (파일이 없다·권한) |
| 4 | 쓰기 실패 |
| 5 | 파일이 깨졌다 (JSON 이 안 읽힌다·`형식` 이 모르는 값) |

오류 글은 전부 한국어로 stderr 에 쓴다.

### 명령 하나하나

#### `stage init [--force]`

| 무엇 | 값 |
| --- | --- |
| 하는 일 | `Docs/Todo/기획상태.json` 을 1단계·1판으로 새로 만든다. 폴더가 없으면 만든다 |
| 상태 변화 | 파일 생성. `단계 1` · `판번호 1` · `판시작일` 오늘 · 배열 둘은 빈 값 |
| 이미 있으면 | 아무것도 안 하고 종료 1. `--force` 면 덮어쓴다 |
| 종료 코드 | 0 / 1 / 4 |

```
기획상태.json 을 만들었습니다 — 1단계 「컨셉」 · 1판.
```

#### `stage show [--json] [--hook]`

읽기만 한다.

| 어떻게 불렀나 | 상태 파일이 없으면 |
| --- | --- |
| `stage show` | **종료 3** + stderr 에 `stage init` 안내 |
| `stage show --hook` | **종료 0** + stdout 에 안내문 한 줄 (「아직 기획상태.json 이 없습니다 — `stage init` 으로 시작하세요」) |

**세션 훅은 `--hook` 으로 부른다.** 훅이 0 이 아닌 값으로 죽으면 세션 문맥에 아무것도 안 들어가고 오류만 남는다.

```
지금 5단계 「거친 프로토타입 묶음」 · 2판 · 3일째
끝났다고 보는 기준 : 각각 5분 동안 손으로 돌아간다

이번 판 물음 2개 — 통과 1 · 불통 0 · 대기 1
  [통과] start-slots  시작 칸을 3칸으로 하는 게 맞나
  [대기] wait-time    기다리는 시간이 30초면 지루한가

되돌아간 횟수 1회.
되돌아가는 조건 : 모양이 틀렸으면 3단계 · 숫자만 틀렸으면 5단계 · 기준이 틀렸으면 4단계.
단계를 넘기는 것은 사용자만 합니다.
```

`--json` 은 상태 파일에 셈한 값(며칠째·되돌아간 횟수)을 얹어 그대로 뱉는다. 대시보드와 다른 툴이 쓴다.

#### `stage next`

| 무엇 | 값 |
| --- | --- |
| 하는 일 | 단계 +1 |
| 기준을 어떻게 다루나 | **막지 않고 경고만 한다.** 지금 단계의 「끝났다고 보는 기준」을 stdout 에 되뇌고, `lint` 의 모양 검사를 돌려 걸리는 것이 있으면 「⚠」 로 같이 보여준 뒤 그대로 넘긴다 |
| 왜 경고만인가 | 단계를 넘기는 것은 **사용자만** 한다는 원칙 때문이다. 툴이 막으면 사용자가 자기 판단을 못 쓴다 |
| 9단계에서 | 종료 1 (「마지막 단계입니다」) |
| 종료 코드 | 0 / 1 / 3 / 4 |

#### `stage back <단계> --why "…"`

| 무엇 | 값 |
| --- | --- |
| 인자 | 되돌아갈 단계 번호. 지금 단계보다 작아야 한다 |
| `--why` | **없으면 종료 1.** 몇 판 돌았나가 판단 재료라 까닭이 비면 뜻이 없다 |
| 상태 변화 | 1절 표대로 |
| 종료 코드 | 0 / 1 / 3 / 4 |

```
6단계 → 3단계 로 되돌아갑니다. 3판 시작 (2026-09-07).
까닭 : 고리가 안 닫혔다
3판째입니다 — 이번에도 통과 못 하면 컨셉이나 기둥을 의심할 때입니다.
```

#### `stage ask "<물음>" --crit "…" [--crit "…"] [--id <손잡이>]`

물음을 상태 파일에 넣는 명령이다. 이름은 `ask` 로 정했다 — 4단계가 「물음 묶음」이라 말이 그대로 붙는다.

| 무엇 | 값 |
| --- | --- |
| 인자 | 물음 한 문장 |
| `--crit` | 판정 기준. **여러 번 쓴다.** 하나도 없으면 종료 1 |
| `--id` | 없으면 물음 앞머리에서 만든다 (영문·숫자·`-` 만 남기고, 겹치면 뒤에 `-2`) |
| 상태 변화 | `물음[]` 에 한 줄. `상태` 는 `만드는중`, `판번호` 는 지금 판, `만든날` 은 오늘 |
| 경고 | 이번 판 물음이 설정의 `물음개수` 범위를 넘으면 경고만 하고 넣는다 |
| 종료 코드 | 0 / 1 / 3 / 4 |

플래그 이름은 영어다 (`--crit` · `--why` · `--note`). 출력과 도움말만 한국어다 — 「코드 이름은 영어」 규칙을 플래그까지로 본다.

#### `stage check <id> pass|fail --note "…"`

| 무엇 | 값 |
| --- | --- |
| 상태 변화 | 그 물음의 `판정` 에 한 줄 더하고 `상태` 를 `통과`/`불통` 으로 덮는다 |
| `--note` | 없어도 된다. 다만 `fail` 이면 **경고**한다 (「왜 불통인지 없으면 다음 판에 못 쓴다」) |
| 없는 id | 종료 1. 비슷한 id 를 세 개까지 알려준다 |
| 덧붙임 | `fail` 이면 절차 정본의 되돌아가는 표 세 줄을 그대로 보여준다 (모양 → 3단계 · 숫자 → 5단계 · 기준 → 4단계) |
| 종료 코드 | 0 / 1 / 3 / 4 |

#### `stage lint [<파일…>] [--hook]`

4절에서 따로 적는다.

#### `stage dash [--out <경로>]`

| 무엇 | 값 |
| --- | --- |
| 하는 일 | `Docs/Todo/대시보드.html` 한 장을 굽는다 (`--out` 으로 자리를 바꾼다) |
| 종료 코드 | 0 / 3 / 4 |

```
Docs/Todo/대시보드.html 를 구웠습니다 (2026-09-07 21:10). 브라우저로 여세요.
```

붙은 저장소의 `.gitignore` 에 `Docs/Todo/대시보드.html` 를 넣으라고 `README` 에 적는다. **낡은 사진이 정본처럼 보이면 안 된다.**

#### `stage version` · `stage help [<명령>]`

`stage 0.1.0` 한 줄. 도움말은 한국어. 인자 없이 부르면 도움말 + 종료 1.

## 4. `lint` — 셀 수 있는 것만 본다

**두 가지로 부른다.**

- `stage lint <파일…>` — 그 파일들을 「이제 쓰려 한다」고 치고 검사한다.
- `stage lint --hook` — stdin 으로 훅 JSON 을 받아 `tool_input.file_path` 하나를 뽑아 같은 검사를 한다.
- 인자도 `--hook` 도 없으면 **저장소 전체의 모양 검사만** 한다 (순서 검사는 대상 파일이 있어야 뜻이 있다).

**검사 대상 밖** : 설정의 `프로토타입폴더` 아래 전부, `Docs/Todo/대시보드.html`, `.git/`.
버릴 코드를 훅이 막으면 5단계가 답답해져서 아무도 프로토타입을 안 만든다.

| # | 검사 | 언제 (대상) | 무엇을 세나 | 막나 |
| --- | --- | --- | --- | --- |
| L1 | 문서 순서 | `기획문서폴더` **바로 아래** `NN-…md` 를 쓰는데 그 파일이 **아직 디스크에 없을 때** | 뼈대 목록에서 그 파일보다 **앞 순번 파일이 다 있나** | **막는다** |
| L2 | 코드 순서 | `코드폴더` 가 설정돼 있고 그 아래 **새 파일**을 쓸 때 | `03-시스템-*.md` 가 하나라도 있나 | **막는다** |
| L3 | 파일 이름 | `기획문서폴더` **바로 아래**의 `.md` 를 쓸 때. 하위 폴더는 검사 밖 | 이름이 `^\d\d-.+\.md$` 인가 | **막는다** |
| L4 | 기둥 개수 | `00-컨셉.md` 를 쓸 때 · 전체 검사 | `## 기둥` 아래 첫 표의 본문 줄 수가 `기둥개수` 범위인가 | 단계 ≤ 2 면 경고 · **단계 ≥ 3 이면 막는다** |
| L5 | 컨셉 길이 | `00-컨셉.md` 를 쓸 때 · 전체 검사 | 파일 줄 수가 `컨셉줄상한` 이하인가 | 경고 |
| L6 | Won't 칸 | `02-기능목록.md` 를 쓸 때 · 전체 검사 | MoSCoW 표에서 첫 칸이 `Won't` 인 줄이 하나 이상인가 | 단계 ≤ 7 이면 경고 · **단계 ≥ 8 이면 막는다** |
| L7 | 물음 개수 | 전체 검사 · `next` | 이번 판 물음 수가 `물음개수` 범위인가 | 경고 |
| L8 | 상태 파일 앞뒤 | 늘 | `상태` 가 `판정` 의 마지막 값과 맞나 · `단계` 가 1~9 인가 · id 가 겹치나 | 경고 (5번 깨짐은 종료 5) |

**늘 막는 검사는 셋(L1·L2·L3)뿐이고, 둘(L4·L6)은 단계에 따라 막는다.** 판단이 섞이는 것은 하나도 안 넣는다.

**왜 단계를 보나** — 문서는 단계마다 하나씩 쓴다. 1단계에서 컨셉 한 문장만 먼저 적으면 기둥은 아직 0개다(기둥은 2단계).
`02-기능목록.md` 의 Won't 칸도 7단계에서 채우는 것이라 그 전에 막으면 문서를 시작조차 못 한다.
그래서 **그 단계가 지나간 뒤에만 막는다.** 그 전에는 경고로 알려만 준다.

### 마크다운을 세는 규약

훅이 세려면 **어디를 어떻게 세는지 문서에 못 박혀** 있어야 한다. 아래가 그 규약이다. 붙은 저장소의 문서는 이 모양을 지켜야 한다.

| 무엇 | 어디를 보나 | 세는 법 |
| --- | --- | --- |
| 기둥 | `00-컨셉.md` 안에서 `## 기둥` 으로 시작하는 제목 (뒤에 글자가 더 붙어도 된다 — `## 기둥 3~4개`) | 그 제목부터 **다음 `##` 제목 전까지** 사이의 **첫 표**의 본문 줄. 머리줄과 `---` 구분줄은 안 센다. 그 사이에 표가 없으면 「기둥 표 없음」이다 |
| Won't | `02-기능목록.md` 안 **첫 표** | 첫 칸(`\|` 로 자른 뒤 앞뒤 공백·굵게 표시 `**` 를 떼고)이 `Won't` 인 본문 줄 수 |
| 컨셉 길이 | `00-컨셉.md` | 파일 전체 줄 수 (빈 줄 포함) |
| 표 판별 | — | `\|` 로 시작하는 줄이 이어지는 덩이. 두 번째 줄이 `\|---\|` 꼴이면 머리줄이 있는 표다 |

### 「쓰고 난 뒤」를 어떻게 세나

파일을 쓰기 **전**에 부르는 검사라 디스크에는 아직 옛 내용이 있다. 그래서 **쓰고 난 뒤를 미리 만들어서** 센다.

| 도구 | 무엇을 세나 |
| --- | --- |
| `Write` | `tool_input.content` 그대로 |
| `Edit` | 디스크 내용에 `tool_input.old_string` → `new_string` 을 **적용한 결과**. `replace_all` 이 참이면 다 바꾸고, 아니면 첫 번째만 |
| `Edit` 인데 `old_string` 이 없거나 디스크에서 못 찾음 | 디스크 내용 그대로 (바뀌는 것을 모르니 지금 것으로 본다) |
| 디스크에 파일이 없음 | 빈 글로 본다 |

이렇게 하면 **이번 고침으로 고쳐질 문제 때문에 막히는 일**이 없다. 예를 들어 기둥을 3개로 채우는 `Edit` 은 통과해야 맞다.

## 5. 훅 셋

붙은 저장소의 `.claude/settings.json` 에 아래를 더한다. 이미 있는 훅 배열에는 **줄을 더하기만** 한다.

```json
{
  "hooks": {
    "SessionStart": [
      {
        "matcher": "startup|resume|clear|compact",
        "hooks": [
          {
            "type": "command",
            "command": "Tools/GamedesignTool/bin/stage.exe",
            "args": ["show", "--hook"],
            "timeout": 10,
            "statusMessage": "기획 단계 읽는 중"
          }
        ]
      }
    ],
    "PreToolUse": [
      {
        "matcher": "Write|Edit",
        "hooks": [
          {
            "type": "command",
            "command": "Tools/GamedesignTool/bin/stage.exe",
            "args": ["lint", "--hook"],
            "timeout": 10,
            "statusMessage": "기획 순서 검사 중"
          }
        ]
      }
    ],
    "Stop": [
      {
        "hooks": [
          {
            "type": "command",
            "command": "Tools/GamedesignTool/bin/stage.exe",
            "args": ["done", "--hook"],
            "timeout": 10
          }
        ]
      }
    ]
  }
}
```

### 입출력 규약 (공식 문서 확인 : https://code.claude.com/docs/en/hooks — 2026-09-07 확인)

| 훅 | stdin 으로 오는 칸 | 우리가 쓰는 것 | 나가는 길 |
| --- | --- | --- | --- |
| `SessionStart` | `session_id` · `transcript_path` · `cwd` · `hook_event_name` | `cwd` (뿌리로 삼는다) | **종료 0 + stdout 이 문맥에 들어간다.** `stage show` 출력을 그대로 쓴다 |
| `PreToolUse` | 위 + `tool_name` · `tool_input` · `tool_use_id` · `permission_mode` | `tool_input.file_path` · `tool_input.content` | **종료 2 + stderr 가 막는 까닭으로 Claude 에게 간다.** 통과면 종료 0 · 출력 없음 |
| `Stop` | 위 + `stop_reason` · `last_assistant_message` | 아무것도 안 쓴다 (파일만 본다) | **stdout 평문은 Claude 가 못 본다.** 그래서 종료 0 + stdout 에 `{"systemMessage": "…"}` JSON 을 낸다 |

- 훅 설정의 `matcher` 는 `PreToolUse` 에서 도구 이름을 가린다 (`Write|Edit`). `Stop` 은 matcher 를 안 쓴다.
- `command` + `args` 를 나눠 적으면 셸을 안 거친다. 경로에 공백이 있어도 안전하다.
- **`bin/` 은 gitignore 라 저장소를 받은 직후에는 exe 가 없다.** 그때 훅은 그냥 **실패하고 아무것도 막지 않는다**
  (`PreToolUse` 는 0 도 2 도 아닌 값이라 비차단). 검사가 조용히 안 도는 것이므로,
  받은 직후 한 번 빌드하라는 줄을 `README` 에 적는다.
- **훅으로 부르는 명령은 stdin 을 반드시 끝까지 읽고 버린다.** 안 읽으면 부르는 쪽에서 파이프가 막힐 수 있다.
- **`Stop` 에서 종료 2 나 `block` 을 쓰면 대화가 안 끝난다.** 우리는 **경고만** 하기로 했으니 쓰지 않는다.

### `stage done --hook` — Stop 훅이 부르는 것

판 끝에 할 일 셋(플레이 기록 · 기억 1건 · 진행 상황 문서 고치기)이 빠졌는지 본다. **막지 않는다.**

| 볼 것 | 어떻게 |
| --- | --- |
| 플레이 기록 | 이번 판 물음이 **다 판정됐는데** `Docs/History/` 아래 `판시작일` 이후로 고쳐진 `.md` 가 없으면 경고. **폴더 자체가 없으면 「기록 없음」으로 본다** (오류가 아니다) |
| 기억 1건 | 기억 저장소를 부르지 않는다 — **1판에서는 안 본다.** 대신 「기억 1건 남겼나」를 글로 되묻는다 |
| 진행 상황 문서 | `Docs/Todo/진행상황.md` 의 고친 시각이 `판시작일` 보다 이르면 경고 |

경고가 없으면 **아무것도 출력하지 않는다.** 매번 떠드는 훅은 곧 무시당한다.

```json
{ "systemMessage": "판 끝 할 일이 남았습니다 : 플레이 기록 · 진행 상황 문서 고치기" }
```

## 6. `dash` 화면 배치

**한 장 · 덩어리 여섯 · JS 로직 없음** (Mermaid 렌더만 예외). 위에서 아래로 읽는다.

| # | 덩어리 | 어떻게 그리나 | 데이터 출처 |
| --- | --- | --- | --- |
| ① | **9단계 스테퍼** — 지난 단계 채움 · 지금 강조 · 앞은 흐리게. 옆에 「2판째」 | CSS 그리드 9칸 | 상태 파일 `단계`·`판번호`, 설정의 단계 이름 |
| ② | **지표 타일 3개** — 되돌아간 횟수 / 이번 판 물음 통과 수 (`2 / 4`) / 이번 판 며칠째 | CSS 카드 3장 | `되돌아간기록` 길이 · `물음[]` 중 지금 판 · `판시작일` 부터 오늘까지 |
| ③ | **이번 판 물음 목록** — 물음 한 줄 + 상태 딱지 + 기준 개수 | 표 한 개 | `물음[]` 중 `판번호` 가 지금 판인 것 |
| ④ | **기둥 상자** — 3~4개 | 목록 | `Docs/Design/00-컨셉.md` 의 `## 기둥` 아래 첫 표 (4절 규약대로 읽는다) |
| ⑤ | **문서 뼈대 체크 6줄** — 있음/없음 | 목록 | 설정 `문서뼈대` 와 실제 파일 |
| ⑥ | **되돌아가는 고리 상태도** — 3→4→5→6→3 | Mermaid `stateDiagram-v2` | 절차 정본의 되돌아가는 표 (코드에 박는다) |

맨 아래 한 줄에 **구운 시각**. 「이 화면은 사진입니다 — 정본은 `Docs/Todo/기획상태.json` 입니다」 도 같이 적는다.

- CSS 는 **인라인**이다. 바깥 파일을 안 쓴다.
- Mermaid 는 CDN `<script>` 한 줄. **오프라인 대비** : `<pre class="mermaid">` 안에 도면 글을 그대로 넣어 두고,
  스크립트가 안 뜨면 그 글이 `<pre>` 로 보인다. 밑에 「3 → 4 → 5 → 6 → 3 (불통이면 되돌아간다)」 글자 줄을 하나 더 둔다.
- **다른 툴(기억 저장소·공수 툴)의 값은 1판에 얹지 않는다.** 정본이 둘이 되는 것을 막는 가장 싼 방법은 안 얹는 것이다.

## 7. 패키지 나누기와 시험

### `internal/` 아래

| 패키지 | 맡는 것 | 밖으로 내는 것 |
| --- | --- | --- |
| `config` | 9단계 기본값 + `기획설정.json` 덮기 | `Load(root) (Config, error)` · `Config.Stage(n)` |
| `state` | 상태 파일 읽기·쓰기, 판 번호·되돌아간 기록 규칙 | `Load` · `Save` · `Next` · `Back` · `Ask` · `Check` |
| `mdscan` | 마크다운에서 표를 찾아 세기 (기둥·Won't·줄 수) | `Pillars(src)` · `WontRows(src)` · `Tables(src)` |
| `lint` | 검사 규칙 L1~L8. `state`·`mdscan`·`config` 를 쓴다 | `Run(ctx Target) []Finding` |
| `hookio` | 훅 stdin JSON 읽기, `systemMessage` JSON 만들기 | `ReadPreToolUse` · `ReadStop` · `WriteSystemMessage` |
| `dash` | `html/template` + `embed` 로 HTML 굽기 | `Bake(w, Model) error` |
| `paths` | 뿌리 정하기, 경로 정규화, 검사 제외 판단 | `Root(flag)` · `Rel` · `Excluded` |
| `render` | 터미널 표·딱지 그리기 (한글 폭 셈) | `Table` · `Badge` |

- **`cmd/stage/main.go` 는 갈래·플래그·종료 코드만** 맡는다. 셈은 전부 `internal` 에 둔다. 같은 스튜디오의 공수 툴과 같은 결이다.
- 종료 코드를 달고 다니는 오류 자료형(`codedError`)도 같은 결로 `cmd` 에 둔다.
- `lint` 는 `state` 를 고치지 않는다 — **검사는 쓰지 않는다.**

### 시험

`go test ./...` 하나로 돈다. 표를 늘어놓는 시험(table-driven)으로 쓴다.

| 무엇 | 어떻게 |
| --- | --- |
| `state` | 판 번호가 오르는 다섯 갈래(`next`·`back 3`·`back 1`·`back 7` 막힘·`check`)를 표로 |
| `mdscan` | 기둥 표 3줄·4줄·5줄·표 없음·제목만 있고 빈 줄 · Won't 있음/없음 |
| `config` | 설정 파일 없음 · 일부 칸만 덮기 · 모르는 칸 무시 · `단계` 배열이 9개가 아닐 때 |
| `lint` | L1~L8 각각 걸리는 예와 안 걸리는 예 |
| `hookio` | 실제 훅 JSON 한 벌을 stdin 으로 넣어 `file_path` 를 뽑나 |
| `dash` | 구운 HTML 에 덩어리 여섯의 표시(`id="stepper"` 등)가 다 있나 · `html/template` 이 꺾쇠를 막나 |

`testdata/` 에 **작은 예시 저장소 하나**를 통째로 둔다.

```
testdata/
  repo-ok/            ← 다 갖춰진 저장소 (검사 전부 통과)
    Docs/Todo/기획상태.json
    Docs/Todo/기획설정.json
    Docs/Design/00-컨셉.md      ← 기둥 표 3줄
    Docs/Design/01-코어루프.md
    Docs/Design/02-기능목록.md  ← Won't 두 줄
    Prototypes/버릴것.md        ← 검사에서 빠지는지 보는 미끼
  repo-bad/           ← 기둥 5개 · Won't 빈 칸 · 01 만 있고 00 이 없다
  hooks/pretooluse-write.json  ← 훅 stdin 예시
```

## 8. 2판으로 미룬 것

| 무엇 | 왜 |
| --- | --- |
| 프로토타입 갤러리 탭과 `proto-meta` 읽기 | 프로토타입이 둘 이상 쌓인 뒤에 만든다 |
| 기억 저장소·공수 툴 값 얹기 | 정본이 둘이 되는 위험이 가장 큰 자리다. 1판은 안 얹는다 |
| 조사 문서 7장 ②의 「`진행상황.md` 맨 위 한 줄을 툴이 고치기」 | 남의 문서를 쓰는 명령이라 1판 범위 밖. `done` 훅이 **경고만** 하는 것으로 대신한다 |
| MoSCoW 칸 옮기기 명령 | 문서를 직접 고치면 된다. CLI 로도 과하다 |
| 웹에서 통과/불통 적기 (로컬 서버) | 6단계를 한 번 실제로 돌려 본 뒤 정한다 |
| `stage lint` 의 자동 고치기 | 검사와 고치기를 한 명령에 섞으면 훅에서 위험하다 |

**1판에서 뺀 이유가 공수인 것은 하나도 없다.** 다 「아직 재료가 없다」거나 「정본이 둘이 된다」다.

| 2 | `형식` 칸 | 정수 1. 모르는 값이면 종료 5 | 모양이 바뀔 때 조용히 깨지는 것을 막는다 |
| 3 | 물음 상태 값 | `만드는중`·`대기`·`통과`·`불통` 넷 | 2판 칸반 열 네 개와 그대로 맞는다 |
| 4 | `상태` 와 `판정` | `판정` 이 정본, `상태` 는 뽑아 둔 값. L8 이 어긋남을 본다 | 사람이 눈으로 읽으려면 딱지가 필요하다 |
| 5 | 판 번호가 오르는 때 | **`back` 으로 3~6 안에서 되돌아갈 때만.** `next` 로는 안 오른다 | 「3판 돌아도 통과 못 하면」을 그대로 셀 수 있다 |
| 6 | `back 1\|2` | 판 번호를 1로 되돌린다. 기록은 안 지운다 | 컨셉이 바뀌면 고리도 새로 세는 게 맞다 |
| 7 | 물음 넣는 명령 이름 | `stage ask "<물음>" --crit "…"` | 4단계가 「물음 묶음」이라 말이 그대로 붙는다 |
| 8 | 플래그 이름 | 영어 (`--crit`·`--why`·`--note`·`--root`·`--out`·`--hook`). 출력·도움말만 한국어 | 「코드 이름은 영어」를 플래그까지로 봤다 |
| 9 | `next` 와 기준 | **막지 않고 경고만.** 모양 검사 결과를 같이 보여준다 | 「단계를 넘기는 것은 사용자만 한다」 |
| 10 | 막는 검사 | 늘 막는 것은 L1·L2·L3 셋. L4(기둥)는 단계 ≥ 3, L6(Won't)은 단계 ≥ 8 부터 막는다 | 그 문서를 쓰는 단계에서 막으면 문서를 시작조차 못 한다 |
| 11 | `Edit` 일 때 내용 검사 | 디스크 내용에 `old_string`→`new_string` 을 적용한 **결과**를 센다 (`replace_all` 존중) | 이번 고침으로 고쳐질 문제 때문에 막히면 안 된다 |
| 11-2 | L1 순서 검사 범위 | **그 파일이 아직 디스크에 없을 때만** 본다 | 이미 있는 문서를 고치는 것은 순서와 상관없다. 옛 문서가 있는 저장소에 붙어도 안 걸린다 |
| 11-3 | L3 이름 검사 범위 | `기획문서폴더` **바로 아래**만. 하위 폴더는 검사 밖 | 옛 자료를 모아 둔 하위 폴더를 이름 규칙으로 막을 이유가 없다 |
| 11-4 | 세션 훅 부르는 꼴 | `show --hook` — 상태 파일이 없어도 종료 0 | 훅이 0 이 아닌 값으로 죽으면 문맥에 아무것도 안 들어간다 |
| 12 | `Stop` 훅 | 종료 0 + stdout `{"systemMessage": …}`. **경고만** | 평문 stdout 은 Claude 가 못 보고, 종료 2 는 대화를 안 끝낸다 |
| 13 | `Stop` 훅 명령 이름 | `stage done --hook` | `lint` 는 파일 검사라 뜻이 다르다 |
| 14 | 종료 코드 2 | **검사 불통** 자리로 쓴다 | 훅이 막는 값과 같아서 껍데기 스크립트가 필요 없다 |
| 15 | 기둥 세는 규약 | `## 기둥` 제목 **바로 다음 첫 표**의 본문 줄 수 | 「어디를 세나」가 문서에 못 박혀야 훅이 셀 수 있다 |
| 16 | Won't 세는 규약 | `02-기능목록.md` **첫 표**의 첫 칸이 `Won't` 인 줄 수 | 표가 여럿일 때 헤매지 않게 첫 표로 못 박았다 |
| 17 | 컨셉 줄 상한 | 60줄 (설정으로 덮음), **경고만** | A4 반 쪽 눈금. 한 줄 넘었다고 막으면 짜증만 난다 |
| 18 | Mermaid 오프라인 대비 | 도면 글을 `<pre class="mermaid">` 에 넣고 아래에 글자 줄 하나 더 | 스크립트가 안 뜨면 글이 그대로 보인다 |
| 19 | 다른 툴 값 얹기 | 1판에 **안 얹는다** | 정본이 둘이 되는 위험이 가장 큰 자리다 |
| 20 | 상태 파일이 없을 때 `show` | 맨손이면 종료 3 + `init` 안내, `--hook` 이면 종료 0 + 안내문 | 훅이 세션을 막으면 안 된다 |
| 21 | exe 가 없을 때 훅 | 그냥 실패하고 아무것도 막지 않는다. `README` 에 빌드 한 줄을 적는다 | `bin/` 이 gitignore 라 받은 직후엔 exe 가 없다 |

## 10. 확신 없는 것

| # | 무엇 | 어떻게 해 뒀나 | 어떻게 확인하나 |
| --- | --- | --- | --- |
| 1 | `Stop` 훅에서 `systemMessage` 가 실제로 사용자·Claude 에게 보이나 | 보인다고 보고 설계했다. 공식 문서 요약이 「대부분의 이벤트에서 문맥에 들어간다」 정도라 `Stop` 만 딱 집어 확인하지 못했다 | 만들고 나서 한 번 돌려 화면에 뜨는지 눈으로 본다. 안 뜨면 **경고를 포기하고 `stage done` 을 사람이 치는 명령으로** 돌린다 |
| 2 | `Stop` 훅 JSON 의 막는 칸 이름 (`decision`/`permissionDecision`) | **안 쓴다** — 막지 않기로 했으니 부딪히지 않는다 | 나중에 막을 일이 생기면 그때 확인한다 |
