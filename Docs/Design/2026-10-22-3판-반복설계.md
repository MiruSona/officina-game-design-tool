# 3판 설계 — 9단계 뒤 반복을 `stage` 로 데려오기 (2026-10-22)

> 근거 조사 : `../Research/2026-10-21-Unity프로토반복조사.md` 추천 1~3 (+ 4 의 일부).
> 절차 정본 : `../Guide/기획절차.md` 「9단계 뒤 — 반복」 절 (이번 판 첫 편집으로 넣음).
> 사용자 결정 (2026-10-22) : ① 정본에 반복 절을 넣는다 ② 3판은 AssetTool 2차보다 먼저 한다.

## 0. 결론 먼저

- **새 단계(10단계)는 만들지 않는다.** 마지막 단계(기본 9) 안에서 `stage iter new` 를 한 번이라도 치면 「반복 중」이다.
  단계 정의·M7(9단계 박힘)을 건드리지 않아 싸고, 다른 게임의 단계 설정도 그대로 둔다.
- 세 기능을 한 판에 만든다.

| # | 기능 | 자리 | 덮는 일 (조사 2절) |
| --- | --- | --- | --- |
| 1 | `stage iter new` — 번호 매기기 · 틀 베끼기 · 놀았던 판 채우기 · 지난 「미룬 것」 옮겨 오기 | 새 명령 | a · b · f |
| 2 | 상태 파일 `반복` 배열 + `show`·`dash` 가 보여 주기 | `state` · `show` · `dash` | b · h |
| 3 | `stage done` 이 반복 끝을 본다 — 고친 것·미룬 것·넘긴 것 · 틀 자리표 · 기억 1건 | `done` (Stop 훅) | e · g · i (+4 의 자리표) |

- **틀은 툴 안에 기본 틀을 품고(내장), 게임이 `반복틀` 설정으로 자기 틀을 줄 수 있다.** 툴은 다른 게임에도 설치되니 특정 저장소 틀을 전제하지 않는다.
- **미룬 것은 원문을 베껴 온다** (가리킴 아님). 까닭은 5절.
- 색인 표(진행 문서의 「반복 기록」)는 상태 파일 `반복` 배열이 대신한다. 툴은 진행 문서 색인을 검사하지 않는다.

## 1. `stage iter new`

```
stage iter new [--played <판>] [--title "<한 줄>"] [--root <뿌리>]
```

| 인자 | 뜻 | 없으면 |
| --- | --- | --- |
| `--played` | 이번에 놀았던 판 (예 `v16`) | 지난 반복의 `올린판` → 없으면 지난 반복의 `놀았던판` → 없으면 `?` |
| `--title` | 이번 반복 한 줄 | 빈 칸 (나중에 손으로) |

하는 일, 차례대로.

1. 상태 파일을 읽는다. **지금 단계가 마지막 단계가 아니면 거절**한다 (종료 1, 「반복은 N단계 「확장」 뒤에 합니다」).
2. 번호 NN = max(상태 파일 `반복` 의 마지막 `회`, 기록 폴더 파일 이름 `^(\d+)-` 의 최댓값) + 1. 두 자리 0 채움(`%02d`). `00` 은 틀 자리라 셈에서 뺀다.
   - 폴더도 같이 보는 까닭 : 이미 손으로 01~09 를 쓴 게임은 상태 파일에 반복이 없다. 첫 `iter new` 가 10 을 내야 한다.
3. 「지난 기록」 = 번호가 가장 큰 기록 파일. 그 파일의 「미룬 것」 을 뽑는다 (5절).
4. 틀을 읽고 자리말(2절)을 채워 `<반복기록폴더>/NN-YYYY-MM-DD.md` 를 쓴다. **같은 이름이 있으면 거절** (종료 1). 덮어쓰기 옵션은 안 둔다.
5. 지난 반복 줄의 `올린판` 이 비었고 `--played` 를 줬으면 그 값으로 채운다 (놀았던 판 = 지난번에 올린 판).
6. 상태 파일 `반복` 에 줄 하나를 더하고 저장한다.
7. 지난 반복에 done 검사(4절)로 빠진 것이 있으면 `⚠` 로 찍는다 (막지 않음).
8. 찍기 : `반복 10 을 열었습니다 — Docs/History/반복/10-2026-10-22.md · 놀았던 판 v16 · 지난 반복에서 미룬 것 4줄 옮김`.

| 종료 코드 | 언제 |
| --- | --- |
| 0 | 만들었다 |
| 1 | 단계가 마지막이 아님 · 같은 파일 있음 · 인자 잘못 · 설정 경로가 뿌리 밖 |
| 3 | 상태 파일 없음 · 틀 파일 못 읽음 |
| 4 | 기록 파일·상태 파일 못 씀 |
| 5 | 상태 파일 깨짐 |

- 명령 꼴은 `iter <하위명령>` 로 둔다. 이번 판 하위명령은 `new` 하나다. `iter` 만 치면 쓰는 법을 찍고 종료 1.
- 쓰기 차례 : 기록 파일 먼저, 상태 파일 나중. 상태 저장이 실패하면 방금 쓴 기록 파일을 지우고 종료 4 (반쪽 상태를 안 남김).

## 2. 틀의 자리와 자리말

| 설정 (`기획설정.json`) | 기본 | 뜻 |
| --- | --- | --- |
| `반복기록폴더` | `Docs/History/반복` | 기록 파일을 두는 폴더 |
| `반복틀` | (없음 → 내장 틀) | 게임 자기 틀 파일. 뿌리 기준 상대 경로 |

- 두 경로 모두 **뿌리 안이어야** 한다. 절대 경로·`..` 로 밖에 나가면 거절 (종료 1). `paths.Rel` 로 막고, 쓰기 자리는 `cmd_conflict.go` 의 `checkOut`·`underReal` 처럼 링크를 푼 실제 경로로 한 번 더 본다.
- 내장 틀은 `templates/iter.md` 로 두고 `dash.html` 처럼 embed 한다. 꼴은 게임 저장소가 9판 동안 쓴 틀과 같은 절 이름을 쓴다 :
  `## 지난 반복에서 미룬 것` · `## 피드백` · `## 결정` · `## 고친 것` · `## 미룬 것` · `## 넘긴 것`.
- 자리말은 `{{…}}` 글자 바꾸기만 한다 (Go `text/template` 안 씀 — 사람이 쓴 틀의 `{` 가 깨지지 않게).

| 자리말 | 채우는 값 |
| --- | --- |
| `{{회}}` | NN |
| `{{날짜}}` | 오늘 `YYYY-MM-DD` |
| `{{놀았던판}}` | 1절 `--played` 값 |
| `{{한줄}}` | `--title` 값 (없으면 빈 글자) |
| `{{지난미룬것}}` | 5절에서 뽑은 줄들 |

- 게임 틀에 `{{지난미룬것}}` 이 없으면 `## 피드백` 줄 바로 위에 `## 지난 반복에서 미룬 것` 절을 끼운다. `## 피드백` 도 없으면 파일 끝에 붙인다.
- **done 이 보는 절 이름 셋(`고친 것` · `미룬 것` · `넘긴 것`)은 고정**이다. 게임 틀도 이 이름을 지켜야 검사가 된다. README 에 적는다.

## 3. 상태 파일에 더하는 칸

`Docs/Todo/기획상태.json` 에 배열 하나를 더한다.

```json
"반복": [
  { "회": 10, "시작일": "2026-10-22", "놀았던판": "v16", "올린판": "v17",
    "한줄": "메인 화면 손질", "기록파일": "Docs/History/반복/10-2026-10-22.md" }
]
```

| 칸 | 꼴 | 비면 |
| --- | --- | --- |
| `회` | 정수 | — (늘 있음) |
| `시작일` | `YYYY-MM-DD` | — |
| `놀았던판` | 글자 | `?` |
| `올린판` | 글자, `omitempty` | 다음 `iter new --played` 가 채움 |
| `한줄` | 글자, `omitempty` | — |
| `기록파일` | 뿌리 기준 `/` 경로 | — |

**옛 상태 파일 호환**

- 읽기 : `반복` 이 없는 옛 파일(형식 1)은 빈 배열로 읽는다. 지금 동작이 그대로다.
- 쓰기 : **`반복` 이 하나라도 있으면 `형식` 을 2 로 쓰고, 없으면 1 로 쓴다.** 새 툴은 1·2 둘 다 읽는다.
  - 까닭 : 옛 exe 는 모르는 칸을 버린 채 저장한다. 형식 2 를 보면 옛 exe 는 「모르는 판」 으로 멈추므로 **반복 기록이 조용히 지워지지 않는다.**
  - 반복을 안 쓰는 게임은 형식 1 그대로라 옛 exe 와 계속 섞어 써도 된다.
- 옛 손 기록(01~09)을 배열로 거꾸로 채우는 일은 안 한다 (미룸 7절).

**`show`**

- `반복` 이 있으면 단계 줄 다음에 한 줄 : `반복 10 · 2026-10-22 부터 · 놀았던 판 v16 · Docs/History/반복/10-2026-10-22.md`.
- 반복 중에는 물음 안내(「`stage ask` 로 적습니다」)와 되돌아가는 조건 줄 대신 `새 시스템은 「기능목록」 Won't 표에 대 보고 사용자가 정합니다.` 를 찍는다. 물음이 실제로 있으면 지금처럼 찍는다.
- `--hook` 도 같은 글이다 (세션 시작 요약에 반복 번호가 뜬다). `--json` 은 `State` 를 품고 있어 `반복` 이 저절로 나간다. 셈 칸 `지금반복`(마지막 `회`, 없으면 0) 하나만 더한다.

**`dash`**

- `Model` 에 `Iters []IterRow` (회 · 시작일 · 놀았던판 · 올린판 · 한줄 · 기록파일). 상태 탭 안 **덩어리 하나**, 최근 것이 위. 기록파일은 상대 링크.
- 반복이 없으면 덩어리를 안 그린다 (지금 화면 그대로). 상한 「한 화면 여섯 덩어리」 안에 든다.

## 4. `stage done` 이 반복 끝을 본다

**언제 보나** : `반복` 이 있고 마지막 반복의 기록 파일 「고친 것」 절에 내용이 생겼을 때. 고친 게 하나라도 적혔다 = 마무리 쪽에 왔다는 뜻이다.
그 전에는 조용하다 (반복 중 매 Stop 마다 잔소리하지 않게). 반복이 없으면 지금 `roundTodos` 그대로다.

**「내용이 있다」 가르기** — 절 안의 줄 중 아래가 아닌 줄이 하나라도 있으면 내용이 있다.
- 빈 줄 · 제목 줄 · 표 머리 줄 · 표 가름 줄(`| --- |`) · 칸이 모두 빈 표 줄
- **틀에 똑같이 있는 줄** (틀 = 1절에서 쓴 그 틀, 자리말 채우기 전 글). 틀의 안내 문장·자리표가 여기서 다 걸러진다. 게임마다 틀이 달라도 같은 규칙으로 된다.
- `- 없음` 처럼 「없음」 이라고 쓴 줄은 **내용으로 친다** (일부러 비웠다는 표시).

**검사 항목** (`iterTodos`)

| # | 항목 | 빠졌으면 할 일 글 |
| --- | --- | --- |
| 1 | 기록 파일이 있다 | `기록 파일이 없습니다 — <경로>` (이것만 「고친 것」 조건 없이 본다) |
| 2 | 「미룬 것」 에 내용 | `「미룬 것」 — 없으면 「- 없음」` |
| 3 | 「넘긴 것」 에 내용 | `「넘긴 것」 — 없으면 「- 없음」` |
| 4 | 틀 자리표가 안 남았다 — 틀의 **목록 줄·표 데이터 줄**이 파일에 그대로 남아 있지 않다 | `틀 자리표가 남았습니다 (N줄) — 예 : <첫 줄>` |
| 5 | 기억 1건 | 지금과 같은 글 (툴이 확인 못 함, 세션당 한 번) |

- 4번은 조사 추천 4(lint 규칙)의 「자리표 남음」 만 떼어 온 것이다. 크기 S 이고 done 에 두면 쓰는 중 PreToolUse 에서 잔소리하지 않는다.
- **종료 코드는 늘 0** — done 은 지금도 경고만 하는 Stop 훅이다. 손으로 쳐도 0 이고 글만 찍는다. 뿌리·설정을 못 읽는 것은 지금과 같다 (훅이면 조용히 0, 손이면 3/5).
- 같은 글은 세션당 한 번만 (`doneAlreadySent` 그대로).
- 판 끝 머리 글은 `반복 NN 끝 할 일이 남았습니다 :` 로 바꾼다 (`todoText` 에 머리 글 인자).

## 5. 「미룬 것」 옮겨 오기 — 원문을 베낀다

- 지난 기록의 `## 미룬 것` 절에서 **목록 줄(`- ` · `* ` · `1. `)과 그 아래 들여 쓴 줄**을 그대로 베낀다. 틀에 똑같이 있는 줄(자리표)은 뺀다.
- 맨 위에 `원문 : 반복 09 기록 (<경로>)` 한 줄을 붙인다. 옮길 줄이 없으면 `- 없음` 한 줄.
- **가리킴(「원문은 NN 기록」 만)이 아니라 베끼기로 정한 까닭**
  1. 새 반복의 결정 표는 미룬 것 하나하나에 「고친다/또 미룬다/안 한다」 를 다시 붙인다. 줄이 눈앞에 있어야 번호를 붙일 수 있다.
  2. 지난 기록은 끝난 기록이라 다시 안 고친다. 두 곳에 있어도 어긋날 일이 없다.
  3. 가리킴만 두면 다음 반복에서 결국 옛 파일을 다시 연다. 원천 표시 한 줄로 어디서 왔는지는 남는다.
     (옮겨 온 4판 중 어느 판이 베끼고 어느 판이 가리켰는지는 세지 않았다 — 조사 2절 f 는 둘 다 있었다고만 적었다)
