## 0. 한 장 요약

**`stage conflict` 는 lint 밖의 새 명령이다.** 서로 다른 기획 문서에서 낱말이 겹치는 문장 짝을 규칙으로 추리고,
PATH 에 `localharness judge` 가 있으면 그 짝을 「반대(B)인가」 물어 **경고 목록**을 찍는다. 막지 않는다. 훅에 안 싣는다.

| 정한 것 | 값 | 까닭 |
| --- | --- | --- |
| 자리 | `cmd/stage/cmd_conflict.go` + `internal/conflict/` (짝 추리기·판정 호출·출력) + `internal/mdscan` 에 `Sentences` 추가 | lint 는 「셀 수 있는 것만」[코드 `lint.go` 첫 줄] — 판단이 섞이는 검사는 밖에 둔다 |
| 훅 | **안 건다.** `--hook` 옵션 없음 | 바깥 서버를 부르는 일은 글 쓰는 순간에 돌면 안 된다 (지연 수 분 · 실패 잦음) |
| 판정기 | `localharness judge --kind support --file 쌍.jsonl --json` 을 **외부 명령**으로 부른다 | AGENTS 11절 — 툴끼리 코드·경로로 안 묶는다. 「PATH 에 있으면 쓰고 없으면 건너뜀」 (조사 5절 권장안) |
| PATH 에 없을 때 | 후보 쌍 목록만 찍고 **종료 0** · 「판정 건너뜀 — 후보 쌍 N개」 | 다른 기계에서도 명령이 죽지 않아야 한다 |
| 경고 기준 | **B(반대)만.** B 확률 ≥ 0.8 「경고」 · 0.5~0.8 「애매」 · 그 아래 침묵. A·C 는 안 찍는다 | 기획 문서는 한 주제를 여러 깊이로 말해 「무관」이 정상이다. 문턱이 둘인 까닭은 확률이 0.23 흔들리기 때문 (실측 0절 6번) |
| 종료 코드 | 경고가 있어도 **0**. 1 쓰는 법 · 3 읽기 실패 · 4 `--out` 쓰기 실패 | 경고는 목록이지 막음이 아니다. 판정 실패도 0 (까닭 한 줄) |
| 상한 | 후보 200쌍 (`--limit`) · 문장 400자 | 1.2초 × 200 = 4분 — 「한 번 ≤ 5분」 안 |
| 끄기 | `기획설정.json` 의 `"어긋남판정": false` → 늘 후보 쌍까지만 (바깥으로 안 보냄) | 기획 글이 밖으로 나가는 일이라 저장소마다 끌 수 있어야 한다 |
| 기록 | 붙은 저장소 `.gamedesign/conflict/` 에 「무엇을 보냈나」 jsonl + 결과 | 나간 글을 나중에 추적할 수 있어야 한다. gitignore 권장 |
| 통과선 | 합성 모순 30쌍 재현율 ≥ 0.9 · 실제 50쌍 오탐 ≤ 10% · 전체 ≤ 5분 | 조사 0절 표 그대로. **재기 전에 못 박음** |

## 1. 흐름

```
문서 폴더 읽기 ─→ 문장 나누기 ─→ 짝 추리기 ─→ (비밀 꼴 거르기) ─→ jsonl 쓰기
                                              │
         --judge 없음 (기본 · 10-08 접음) ─┘→ 목록 찍고 끝 (종료 0)
                                              │
                   PATH 에 localharness 없음 ──┘→ 「판정 건너뜀」 + 목록 (종료 0)
                                              │
                                              ▼
                              localharness judge (외부 명령) ─→ 결과 jsonl 읽기 ─→ B 만 골라 표 (종료 0)
```

- 입력 폴더는 lint 와 같은 `cfg.DesignDir` **바로 아래** `NN-이름.md` 만 (하위 폴더·프로토타입·`paths.Excluded` 는 밖) [코드 `paths.InDir`·`Excluded`].
- `--changed` 는 `gitchanged.Load` 로 바뀐 문서를 모으고, **바뀐 문서 × 나머지 전부** 짝만 본다 (바뀐 쪽끼리도 본다). 바뀐 문서가 0이면 「바뀐 문서가 없습니다」 종료 0.
- 명령 옵션 : `stage conflict [--root] [--changed] [--judge] [--pairs-only] [--json] [--limit N] [--out <jsonl>] [--fresh]`. `--fresh` 는 judge 에 그대로 넘긴다. **판정은 `--judge` 를 줄 때만 돈다** (10-08 접음 · 14절 끝). `--pairs-only` 는 이제 기본이라 효과가 없고, `--judge` 와 같이 주면 판정 안 한다. `--json` 의 요약 객체는 `--judge` 때만이다 — 판정 안 하는 길은 후보 jsonl 줄뿐이라 0쌍이면 stdout 이 비고 안내는 stderr 다 (리뷰 10-08). `--fresh` 를 `--judge` 없이 주면 stderr 에 한 줄 알리고 무시한다.

## 2. 문장 나누기 (`mdscan.Sentences`)

문서 한 장 → `[]Sentence{Line int, Text string, Ctx string}`. 줄 번호는 원문 줄(1부터)이다.

| 줄 꼴 | 어떻게 | 까닭 |
| --- | --- | --- |
| 제목 `#…` | **버린다.** 다음 줄들의 Ctx 에 「절 : <제목>」 으로만 쓴다 | 제목은 주장이 아니다 |
| 코드 펜스 안 · 구분줄 `\|---\|` · 빈 줄 · HTML 주석 | 버린다 | — |
| 표 줄 (`\|` 시작) | **칸 하나 = 문장 하나.** 첫 칸은 문장이 아니라 Ctx 로 간다 : 「절 : <제목> · 줄 머리 : <첫 칸> · 칸 머리 : <그 열의 머리>」 | 기획 문서 본문의 절반 이상이 표 칸이다 (8장 · 표 줄 577 · 줄당 평균 3.4칸 [코드 — 건수만 셈]). 칸만 떼면 주어가 없어 판정이 「무관」으로 샌다 — Ctx 를 evidence 앞에 붙인다 |
| 번호 줄 `1.` · 글머리 `-`·`*` | 표시를 떼고 본문으로 본다. 들여쓴 하위 줄도 같다 | — |
| 본문 | `다.`·`요.`·`음.`·`함.`·`됨.`·`?`·`!` 뒤 공백·줄끝에서 자른다. 한 줄에 한 문장이 대부분이다 (`다.` 끝 493 / 본문 줄 985 [코드]) | 「`1.5`」 같은 소수점은 뒤가 공백이 아니라 안 잘린다 |
| 꾸밈 | `**`·`` ` ``·`_`·링크 `[글](주소)`→글 을 뗀다. 표 칸의 `<br>` 는 공백 | — |
| 버림 | 내용어(3절) 2개 미만 · 400자 초과(앞 400자만 쓰고 「…」) · 제어 문자 제거 | 짧은 칸(「O」·「3」)은 짝이 안 된다. 400자는 judge 입력 길이를 묶는 상한 |

evidence 로 보낼 때 꼴 : `[Ctx] 문장`. claim 은 문장만 (Ctx 는 `id` 에 남긴다). 살균은 **이 한 함수**(`Sentences`)에서만 한다 — 보안 스킬 3번.

## 3. 짝 추리기 (`conflict.Pairs`)

### 3-1. 낱말 토막 (최소선)

1. 공백 · `·` `,` `(` `)` `/` `:` `「」` `()` 따옴표 에서 자른다.
2. 토막 끝의 조사를 **한 번만** 뗀다 — 목록 : `은 는 이 가 을 를 의 에 에서 로 으로 와 과 도 만 까지 부터 에게 처럼 보다 이다 다 로는 에는`. 뗀 뒤 2글자 미만이면 떼기 전으로 되돌린다 (「이」→「이」 같은 한 글자 사고 방지).
3. 남긴다 : 한글 2글자 이상 · 영문·숫자 2자 이상. 소문자로 접는다.
4. 버린다 : 멈춤말 작은 목록 (`그 이 저 것 수 등 때 및 또는 그리고 하다 한다 있다 없다 된다 같다 경우 대한 위한 통해`). **숫자 토막은 「내용어」로 안 세고** 따로 `Nums` 에 둔다.
5. 두 글자씩 겹치는 바이그램은 안 쓴다 — 1차는 낱말 그대로. 오탐이 많으면 그때 더한다 [추정].

### 3-2. 짝 조건

서로 **다른 문서**의 문장 A·B 가

- 내용어 집합이 **2개 이상 겹치고**,
- A 나 B 중 하나라도 **숫자**(`[0-9]+`) 또는 **부정어**(`안 않 못 없 아니 금지 never not no`) 를 품는다.

같은 문서 안은 안 본다. 같은 글이면(공백 접고 같음) 안 본다 — 베낀 줄은 모순이 아니다.

### 3-3. 순서 · 정렬 · 상한

- evidence = **번호가 앞선 문서**(`00-` 가 `03-` 보다 앞) 의 문장, claim = 뒤 문서. 같은 번호면 이름순. 앞 문서가 더 「원천」이라는 가정 [추정].
- 겹친 내용어 수 → 숫자·부정어 둘 다 있음 → 문서 번호 순으로 정렬해 `--limit`(기본 200) 에서 자른다. 잘렸으면 「후보 N개 중 200개만 판정」 한 줄.
- 같은 문장 하나가 짝 **20개 이상** 맺으면 그 문장은 「허브」로 보고 상위 5개만 남긴다 — 「자원」·「건물」 같은 낱말이 든 문장이 전부를 삼키는 것을 막는다 [추정].

### 3-4. jsonl 꼴 (판정 입력 · 측정 셋 재료)

`mem judge support --file` 과 같은 네 칸이다 [문서 명령명세 `mem judge`]. 자리 정보는 `id` 에 넣는다 — 모르는 칸을 judge 가 거부할 수 있다.

```json
{"id":"02-기능목록.md:41|04-수치표.md:17","evidence":"[절 : … · 줄 머리 : …] 문장 A","claim":"문장 B","want":""}
```

`--pairs-only --json` 은 이 줄들을 stdout 에 그대로 찍는다. 사람이 `want` 를 채우면 측정 셋이 된다 (6절).

## 4. 판정 호출

| 단계 | 어떻게 |
| --- | --- |
| 찾기 | `exec.LookPath("localharness")`. **PATH 에 같은 이름이 둘 이상이면 거절**하고 「판정 건너뜀 — PATH 에 localharness 가 N개」 (보안 스킬 9번) |
| 없음 | 「판정 건너뜀 — localharness 가 PATH 에 없음 · 후보 쌍 N개」 + 후보 목록(문서 줄 둘 · 문장 앞 60자). **종료 0** |
| 설정 꺼짐 | `"어긋남판정": false` 면 LookPath 전에 같은 꼴로 건너뛴다 (「설정으로 꺼짐」) |
| 부르기 | 인자 배열로 (셸 안 거침) : `localharness judge --kind support --file <임시.jsonl> --json [--fresh]`. 작업 폴더 = 붙은 저장소 뿌리. 제한 시간 = `min(5분, 쌍 수 × 6초 + 30초)` |
| 읽기 | stdout 줄마다 `{id, letter, prob, probs, ms}` [조사 5절]. 모르는 줄은 세어서 「못 읽은 줄 N」. `id` 로 쌍을 되찾는다. **stdout 이 JSON 이 아니면 그 첫 줄(앞 120자)을 까닭으로 쓴다** — judge 가 설정 없이 「판정 건너뜀 : …」 을 찍고 종료 0 하는 경우 (2026-10-08 고침, 리뷰 #4) |
| 실패 | 종료 코드 ≠ 0 이어도 **읽힌 줄은 쓴다.** 읽힌 줄 0이면 「판정 실패 — <stderr 마지막 줄>」 종료 0. 재시도 없음 |
| 다시 안 묻기 | judge 쪽 판정 기록(해시)이 맡는다 — 같은 쌍은 두 번째부터 공짜다. 이 툴은 기록을 따로 안 둔다 |

판정 글은 mem 의 `support-v1` 정본을 하네스가 베낀 것이다 (조사 5절). **이 툴은 물음 글을 모른다** — 통째로 judge 몫.

## 5. 출력 · 종료 코드

> 출력 꼴의 최신은 14-8 절이다 (줄:칸 · `a_cell`·`b_cell` · 정리 필요 · `kind` · `excluded`). 판정과 아래 판정 출력은 `--judge` 를 줄 때만이다 (10-08 접음).

사람용 (stdout) :

```
어긋남 후보 37쌍 → 판정 37 (경고 2 · 애매 3 · 조용 32) · 1분 02초
┌ 경고 (B ≥ 0.8)
│ 02-기능목록.md:41 ↔ 04-수치표.md:17   B 0.91
│   A : 「[절 : … ] 문장 A …」
│   B : 「문장 B …」
├ 애매 (0.5 ≤ B < 0.8)
│ …
└ 보낸 것 : .gamedesign/conflict/2026-10-08T1012.jsonl (비밀 꼴로 뺀 문장 1)
```

- 문장은 앞 120자. 전체는 기록 파일에.
- `--json` : `{"pairs":37,"judged":37,"skipped":"","warn":[{id,a_doc,a_line,b_doc,b_line,a,b,prob}],"ambiguous":[…],"sent":"<경로>","secret_dropped":1,"ms":62000}`. `skipped` 는 건너뛴 까닭 글(없으면 빈 글).
- 종료 : **0** 잘 됨(경고·건너뜀 포함) · 1 쓰는 법 · 3 폴더·git 못 읽음 · 4 `--out`·기록 못 씀. lint 의 2(걸림)는 **안 쓴다** — 경고로 막지 않는다는 뜻을 코드로 못 박는다.
- 0건일 때 까닭을 말한다 : 「문서 N장 · 문장 M · 짝 조건에 맞는 것 0」 (보안 스킬 8번).
- 0쌍이면(바뀐 문서 없음 포함) 기록 폴더도 last.json 도 안 쓴다 — last.json 은 지난 판 것이 그대로 남는다.

## 7. 측정 절차 · 통과선

통과선 (못 박음) : **합성 모순 30쌍 재현율 ≥ 0.9 · 실제 50쌍 오탐 ≤ 10% · 전체 한 번 ≤ 5분** · flashnext · 영문 글자 · 한 순서 (실측 0절 꼴).
「잡았다」 = 등급이 경고 **또는 애매** (B ≥ 0.5). 오탐 = 경고(B ≥ 0.8) 인데 사람 라벨이 B 가 아님 ÷ 경고 수.

## 10. 열린 질문

1. `localharness judge --json` 이 jsonl 의 **모르는 칸**을 받는가 — 받으면 `a_doc`·`a_line` 를 칸으로 넣고 `id` 를 단순화한다. 하네스 설계 판이 정한다 (이 문서는 「네 칸만」 으로 둔다).
2. judge 출력이 stdout jsonl 이 맞는가, 종료 코드 표(한 줄이라도 못 받으면 2?)는 mem 과 같은가 — 하네스 설계 판 확인 뒤 4절 「읽기」 줄을 맞춘다.
3. `stage dash` 상태 탭에 「어긋남 후보 N (마지막 판정 날짜)」 한 줄을 얹나 — `last.json` 읽기만이라 싸다. 1판 「여섯 덩어리」 상한에 걸려 보류.
4. evidence = 앞 번호 문서라는 가정이 맞나 — `00-컨셉`이 원천이지만 `04-수치표`가 숫자의 정본일 때는 거꾸로다. 측정 ②에서 사람 라벨이 「방향이 거꾸로」를 몇 번 적는지 본다.
5. 바이그램·형태소 없이 낱말 겹침만으로 후보가 너무 많거나(허브) 적은가 — 측정 ① 의 후보 수(예상 100~300 [추정])로 판단.
6. `.gamedesign/` 폴더 이름 — 툴 폴더 밖 저장소에 숨김 폴더를 새로 만드는 첫 사례다. `Docs/Todo/` 아래로 둘 수도 있다 (gitignore 한 줄은 같다).

## 14. 손질 3차 (2026-10-08 저녁 · 실측 10절 「다음 손질 후보」 ①②③ + D 세 번째 통)

**설계만, 코드는 안 고쳤다.** 사용자 결정(10-08 저녁) : ①②③ 을 한다 · ⑤(겹침 기준 3)는 안 건드린다 · D(틀린 건 아니지만 합치거나 정리해야 하는 짝)는 **세 번째 통** — 도구 출력을 「어긋남」·「정리 필요」 둘로 나누고(애매는 그대로), 채점은 B 만 재현율·오탐에 넣고 D 는 「정리 권고 N 중 맞음 M」 으로 따로 센다.

### 14-1. 한 장 요약

| 정한 것 | 값 |
| --- | --- |
| ① 낱말 차이 힌트 | `Hint()` 에 「낱말 A 최소 ↔ B 최대」 토막을 더한다. 한쪽에만 있는 내용어, 상한 = `min(4, 겹침 수)` |
| ② 힌트 상한·순서 | 단위 붙은 값 → `×` 배율 → 맨숫자 순. 비율·좌표(`3/4`·`9:20`·`540×960`)는 한 토막. 상한 4 는 그대로 |
| ③ 수치표 줄 힌트 끄기 | 두 문장 숫자 토막 합이 8 을 넘으면 힌트 없음 |
| D 갈래 자리 | **(가) 권장** — localharness 에 kind `conflict`(글자 넷 A·B·C·D) 를 더하고 stage 가 `--kind conflict` 로 부른다 |
| 눈금 연속성 | 3차 재측정은 **support 한 판 + conflict 한 판** 둘 다 잰다. 통과선 판정은 conflict 판, 1·2차와 견줌은 support 판 |
| 출력 | 사람용 `├ 정리 필요 (D ≥ 0.8)` 구역 · `--json` 에 `tidy` 배열 · `kind` 칸 |
| 통과선 | 7절 그대로 (재현율 ≥ 0.9 · 오탐 ≤ 10% · ≤ 5분). D 는 통과선에 안 든다. **3차 뒤에도 미달이면 `--pairs-only` 를 기본으로 접는다** |

### 14-2. ① 힌트에 낱말 차이

- **규칙 한 문장** : 두 문장의 내용어(`Bag.Words` — 조사 뗀 2자 이상, 멈춤말 뺀 것) 중 **한쪽에만 있는 것**을 「낱말 A x·y ↔ B z」 꼴로 힌트에 더한다. 양쪽 공통은 `countOverlap` 과 같은 집합 셈으로 뺀다.
- **예시** : evidence 「창고는 최소 3칸」 · claim 「창고는 최대 3칸」 → `[다른 토막 : 낱말 A 최소 ↔ B 최대]`. 놓침 6 건(`synth-03·22·23·26·29·30`)이 전부 이 꼴이다.
- **길이 상한** : 한쪽당 `min(4, Overlap)` 개. 겹침이 2 면 한쪽 2 개까지 — 「겹친 만큼만 다른 것을 말한다」 는 뜻이라 긴 문장끼리(겹침 많음)는 넉넉하고 짧은 짝은 짧다. 순서는 문장에 나온 순서(`Bag.Words` 가 이미 등장 순·중복 없음). 상한에 잘린 쪽은 꼬리에 `…` 을 붙인다.
- **`×3` 배율** : 지금 `Tokens` 는 `×` 를 자르는 글자로 안 봐 `×3` 이 「숫자로 시작 안 함」 → 내용어로 샌다 (실측 10절 「`×3` 은 숫자로 안 센다」). **고침** : `startsWithDigit` 옆에 `startsWithScale` — `×`·`x`·`X` 뒤에 숫자가 오면 `Nums` 로 보낸다 (`×1.5`·`x3`). 내용어 `x` 혼자는 2 자 미만이라 원래 안 들어가므로 부작용 없음.
- **어느 함수** : `pairs.go` `Hint()` 에 `wordDiff(a, b Bag, limit int) (onlyA, onlyB []string)` 한 함수를 더한다. `Tokens` 는 `×` 배율 한 줄만 고친다.
- **go test (서버 없음)** : `TestHintWords` — (1) 최소↔최대 가 낱말 줄로 뜬다 (2) 공통 낱말은 안 뜬다 (3) 멈춤말·1자 토막 안 뜬다 (4) 겹침 2 짝은 한쪽 2 개에서 잘리고 `…` 가 붙는다 (5) 다른 낱말 0 이면 낱말 줄 자체가 없다 (6) `×3` 이 값 줄에 뜨고 낱말 줄엔 안 뜬다.
- **부작용 걱정** : 힌트가 길어져 judge 글이 늘면 ⓐ 전체 판 시간(지금 288 초 · 여유 12 초)이 5 분을 넘을 수 있고 ⓑ 2차 때처럼 「소음 힌트」 가 진짜 경고를 애매로 끌어내릴 수 있다. **재는 법** : ⓐ 전체 판 벽시계(7절 ⑤) · 힌트 평균 글자 수를 `last.json` 에 `hint_avg_runes` 로 남겨 2차(힌트 평균)와 견준다 ⓑ 실제 50 의 **진짜 B 1 건·전체 판 진짜 경고 1 건**의 `probs.B` 가 2차 값(0.850 · 0.838) 아래로 내려가면 부작용으로 적는다. 2차 와 같은 셋(v3)이라 쌍별 견줌이 된다.

### 14-3. ② 힌트 상한·순서 · 비율은 한 토막

- **규칙 한 문장** : `onlyIn` 이 상한 4 에서 자르기 **전에** 값 토막을 「단위 붙은 값 → `×` 배율 → 맨숫자」 순으로 늘어놓고, 비율·좌표·시각 꼴은 자르지 않고 한 토막으로 둔다.
- **예시** : B 쪽 숫자 `13·14·3·2·192분` → 지금은 `13·14·3·2` 에서 잘려 `192분` 탈락(`synth-05`) → 손질 뒤 `192분·13·14·3` (`2` 탈락). `3/4` → 지금 `3`·`4` 두 토막 → 손질 뒤 `3/4` 한 토막.
- **단위 붙은 값** = 숫자 뒤에 글자가 더 있는 토막 (`192분`·`20골드`·`1.5배`·`50%`). **맨숫자** = 숫자·소수점·쉼표뿐인 토막. 같은 묶음 안은 등장 순.
- **비율·좌표 한 토막** : `isSeparator` 가 `/`·`:` 를 자르는 글자로 봐 `3/4`·`9:20` 이 쪼개진다. `Tokens` 앞머리에 `ratioRe = \d+(?:\.\d+)?[/:×x]\d+(?:\.\d+)?` 로 먼저 뽑아 `Nums` 에 넣고 본문에선 공백으로 바꾼다. `540×960` 은 지금도 한 토막(`×` 가 자르는 글자가 아님)이지만 같은 길로 통일한다. 날짜 `2026-10-08` 은 `-` 가 자르는 글자가 아니라 이미 한 토막이고 `noiseNumRe` 가 뺀다 — 안 바뀜.
- **어느 함수** : `tokens.go` `Tokens`(비율 선추출) · `pairs.go` `onlyIn` 안에 `rankNums(xs []string) []string` (정렬) · `numKey` 는 그대로.
- **go test** : `TestTokensRatio` — `3/4`·`9:20`·`540×960`·`1.5/2` 가 각각 한 Nums 토막, 본문 내용어엔 안 샘 · `TestHintOrder` — `13 14 3 2 192분` 입력에 `192분` 이 첫째 · `×3` 이 단위 값 다음, 맨숫자 앞 · 상한 4 에서 `2` 탈락 · `TestHintRatioKept` — evidence `3/4` claim `1/2` 면 「값 A 3/4 ↔ B 1/2」.
- **부작용 걱정** : 절 번호 `4-1` 같은 것이 비율로 잡히진 않나(`-` 는 ratioRe 에 없음 — 안 잡힘) · `URL http://…:8080` 같은 꼴은 `:8080` 앞이 글자라 안 잡힘. 시각 `9:20` 과 「9 대 20」 비율이 같은 꼴인데 둘 다 「한 토막」 이 맞으니 가르지 않는다. **재는 법** : 전체 판 `03-시스템-농장.md:158:2|06-아트규칙.md:11:1` (2차 때 애매로 내려간 해상도 짝) 이 경고로 돌아오는지 본다 — 2차 부작용의 되돌림 지표.

### 14-4. ③ 수치표 꼴 줄엔 힌트 끄기

- **규칙 한 문장** : `len(a.Nums)+len(b.Nums) > 8` 이면 `Hint()` 가 빈 글을 돌려준다 (값·낱말·부정어 다 없음).
- **예시** : 수치표 한 줄 칸 「1단계 100 · 2단계 250 · 3단계 500 · 4단계 1000 · 5단계 2000」 (숫자 10) ↔ 다른 표 비슷한 칸 → 힌트 없음. 글이 이미 숫자뿐이라 판정기가 직접 본다.
- **상수** : `hintMaxNums = 8` (②·① 와 같이 `pairs.go` 상수 묶음). 8 은 실측 10절 후보 글 그대로 — 2차 수치표 부작용 짝(해상도)이 숫자 몇 개였는지 재측정 때 `last.json` 에 「힌트 끈 짝 수 `hint_off`」 로 남겨 다음 손질에서 조정한다.
- **어느 함수** : `pairs.go` `Hint()` 첫 줄.
- **go test** : `TestHintOffOnNumericRow` — 숫자 합 9 면 빈 글, 8 이면 힌트 있음(경계) · 숫자 많아도 부정어 줄까지 꺼지는 것 확인(일부러 — 「끈다」 는 전부 끈다).
- **부작용 걱정** : 수치표에서 숫자 하나가 다른 진짜 어긋남(합성 `num` 꼴)이 힌트 없이 묻힐 수 있다. **재는 법** : 합성 `num` 10 중 숫자 합 > 8 인 쌍을 셋에서 세어 두고(`make_sets_v3.py` 출력 map 에 `nums_total` 열 하나 더함) 그 쌍의 재현율을 따로 적는다. 2차 `num 8/10` 보다 내려가면 상한을 12 로 올려 한 판 더 본다.

**권장 (가).** 까닭 셋 : ① D 는 「B 가 아닌 것」이 아니라 **네 번째 뜻**이라 판정기가 골라야 한다(2차에서 D 가 0.52·0.59 애매 구간에 C 와 섞여 있었다 — B 확률 눈금 하나로는 못 가른다). ② (나)는 시간 여유 12 초를 넘기고 조용한 D 를 못 잡는다. ③ 끊기는 눈금은 「support 한 판 더」 로 값싸게 잇는다(judge 두 판 72+43 초 — 한 번 더 돌려도 2 분).

**(가) 가 하네스에서 바꾸는 것** (git 밖 `~/.localharness/src` · 별도 판) :

- `prompts.go` : `prompt` 에 `Letters []string` 칸을 더하고 `letters` 전역을 없앤다. 세 kind 는 `[A B C]`, `conflict` 는 `[A B C D]`. `judge.go` `Ask` 가 `p.Letters` 를 `Choose` 에 넘긴다. `Kinds` 에 `conflict` 추가. 「글자는 세 kind 공통」 주석을 「kind 마다 다르다」 로.
- `cmd_judge.go` `letterOf` 에 `"d", "tidy", "정리", "정리 필요"` → `LetterD`. `Label` 은 prompts 의 `Labels` 가 맡으니 그대로.
- 기록 해시는 `hashOf(kind, p.Version, …)` 라 kind 가 다르면 열쇠가 달라 support 기록과 안 섞인다 — 손댈 것 없음.
- **물음 글 초안 `conflict-v1`** — support-v1 글에 D 한 줄을 더한 꼴. **v3(일부만 받쳐도 지지·모른다 경고)로 올리지 않는다** — 올리면 눈금이 글자 넷 + 기준 글 둘, 두 가지로 한꺼번에 바뀐다.

```
Criterion : 아래 주장이 근거 문장에 의해 뒷받침되는가? 근거에 없는 말을 덧붙였거나 숫자·뜻이 다르면 지지가 아니다.
            같은 규칙을 다른 말로 적었을 뿐이면 어긋남이 아니라 정리 필요다.
            주장 :
A  지지 — 근거가 주장을 뒷받침한다
B  어긋남 — 근거가 주장과 어긋난다 (뜻이 뒤집힘 · 숫자가 다름)
C  무관 — 근거만으로는 주장을 말할 수 없다
D  정리 필요 — 같은 규칙을 두 글이 다른 말·다른 자리에 적어 합치거나 정리해야 한다 (틀린 것은 아님)
Labels : A 지지 · B 어긋남 · C 무관 · D 정리 필요
```

- 시스템 글(`judgeSystem`)은 그대로 — 「exactly one option」 이라 넷이어도 맞다. `readChoice` 는 top 20 안에서 글자만 고르니 `D` 토큰이 들면 그대로 읽힌다 [코드 `client.go`]. **영문 글자 넷이 top-20 안에 늘 드는지는 안 재 봤다** — 재측정 때 `probs` 에 `D` 키가 빠진 줄 수를 센다(없으면 0 으로 읽혀 조용히 「정리 아님」 이 된다).

**stage 쪽** : `judge.go` `Run` 의 인자 `--kind support` 를 `--kind conflict` 로, `Verdict` 에 `ProbD()` 추가. **하네스가 `conflict` 를 모르면**(옛 하네스 · 종료 1 「--kind 는 support | claim | item 중 하나」) `FailReason` 에 그 글이 들어와 「판정 실패」 로 끝난다 — 그 대신 **한 번 `--kind support` 로 되돌아 다시 돈다**(`kindFallback`). 되돌아간 판은 D 구역 없이 2차 꼴 출력, 꼬리줄에 「판정기가 conflict 를 몰라 support 로 물음 — 정리 필요 구역 없음」. `--json` 에 `"kind":"support"|"conflict"` 칸을 더해 어느 물음이었는지 남긴다. `last.json` 에도 같은 칸.

### 14-6. 측정 절차 — support 한 판 · conflict 한 판

7절 ①~⑥ 그대로 두고 ④ 만 두 겹이 된다. 셋은 v3 그대로(`real-50.jsonl` 라벨 A 33 · B 1 · C 13 · D 3 · `synth-30.jsonl` num/neg/flip 10 씩). 3차 에서 셋은 **안 바꾼다** — 힌트 손질만 재는 판이라 2차와 같은 자여야 한다.

| 판 | 명령 | 무엇을 보나 |
| --- | --- | --- |
| support | `localharness judge --kind support --file real-50.jsonl · synth-30.jsonl --fresh --json` | **1·2차와 이은 눈금.** ①②③ 힌트 손질만의 효과. 2차 20/30 · 1/2 과 쌍별 견줌 |
| conflict | 같은 명령 `--kind conflict` | **통과선 판정은 이 판.** 재현율·오탐은 B 로, D 는 14-7 셈 |
| 전체 | `stage conflict --root <복사본> --fresh --json` 한 번 (기본 conflict) | 벽시계 ≤ 5 분 · 경고·애매·정리 필요 수 · `hint_avg_runes`·`hint_off` |

- 돌리는 순서는 support 두 셋 → conflict 두 셋 → 전체. judge 넉 판 ≈ 4 분 + 전체 5 분. **게임 서버 내려간 뒤**(7절 ④ 규칙 그대로) · 실측 중 다른 세션 금지.
- 두 판의 B 확률 차이를 실측 문서에 한 줄 적는다 : 「conflict 판에서 B 가 support 판보다 평균 얼마 내려갔나(선택지가 넷이라 B 몫이 D 로 샐 수 있다)」. 이 값이 다음부터 conflict 눈금만 쓸 때의 환산 근거다. 4차부터는 support 판을 안 돌린다.
- `run.ps1` 은 `-Kind support|conflict|both`(기본 both) 를 받아 `sets/<셋>.<kind>.out.jsonl` 로 나눠 쓴다. 지금 `real-50.out.jsonl` 꼴은 `*.support.out.jsonl` 로 이름을 옮긴다(2차 결과는 `*.v3.out.jsonl` 로 남김).

### 14-7. D 채점 규칙 — `run.ps1` 셈

라벨은 입력 파일 `want` 를 id 로 되찾는다(손질 1차 ⑤ 그대로 — judge 가 D 를 알아도 입력 want 가 정본). 기존 지표 줄 셋은 **B 만** 본다 :

| 지표 | 셈 | 3차에서 바뀌는 것 |
| --- | --- | --- |
| 합성 재현율 | `probs.B ≥ 0.5` 인 합성 쌍 ÷ 30 | 그대로 |
| 실제 오탐 | 경고(`B ≥ 0.8`) 중 want ≠ B ÷ 경고 수 | **want = D 인 경고는 분자에서 뺀다** (사용자 결정 — D 가 어긋남 쪽으로 떠도 오탐 아님). 분모는 그대로 경고 수 |
| 전체 시간 | `full.out.json` `ms` | 그대로 |

새 줄 하나 : **「정리 권고 N 중 맞음 M · D 놓침 K」**

- N = 실제 50 에서 `probs.D ≥ 0.8` 인 쌍 수(정리 권고). M = 그중 want = D. 권고 정확도 = M ÷ N (N = 0 이면 「권고 0」 만 찍음).
- K = want = D 인데 `D < 0.8` 인 쌍 수 — **「정리 필요」 쪽으로 못 뜬 것만** D 놓침이다. 어긋남 경고로 뜬 D 는 놓침도 오탐도 아니다(둘 다 안 센다 — 사용자 결정). D 셋 3 건이라 K 는 0~3.
- 「애매」(0.5 ≤ B < 0.8) 셈은 그대로. 한 쌍이 B ≥ 0.8 **과** D ≥ 0.8 둘 다인 일은 확률 합 ≤ 1 이라 없다. B 와 D 가 둘 다 0.5~0.8 이면 B 쪽(애매)으로만 센다 — 출력도 같다(14-8).
- support 판은 D 열이 없으니 이 줄이 「(support 판 — D 없음)」 으로 찍힌다.
- `summary.txt` 꼬리에 「--- 정리 권고 id ---」 (id · D · want) 목록을 더한다.

### 14-8. 출력 변경 (5절 위에)

사람용 :

```
어긋남 후보 200쌍 → 판정 200 (경고 2 · 애매 9 · 정리 필요 3 · 조용 186) · 4분 48초
┌ 경고 (B ≥ 0.8)
│ …
├ 애매 (0.5 ≤ B < 0.8)
│ …
├ 정리 필요 (D ≥ 0.8)
│ 02-기능목록.md:33:2 ↔ 03-시스템-농장.md:11:5   D 0.86
│   A : 「…」
│   B : 「…」
└ 보낸 것 : … (판정 conflict-v1)
```

- 가르는 순서 : `B ≥ 0.8` 경고 → `D ≥ 0.8` 정리 필요 → `B ≥ 0.5` 애매 → 조용. 정리 필요가 애매보다 앞선다(확실한 D 가 흔들리는 B 보다 사람에게 쓸모가 있다). 조용 = 판정 − 셋.
- 구역 순서는 경고 · 애매 · 정리 필요 — 「고쳐야 할 것」 둘 다음에 「정리하면 좋을 것」.
- `--json` : `"tidy":[{id,a_doc,a_line,a_cell,b_doc,b_line,b_cell,a,b,prob}]` (prob = D 확률) 와 `"kind":"conflict"`. support 로 되돌아간 판은 `tidy: []` · `kind: "support"`. `hit` 꼴은 그대로 쓴다 — 칸 이름 `prob` 이 B 인지 D 인지는 배열 이름이 말한다.
- 문턱 상수 `tidyProb = 0.8` (`cmd_conflict.go` 상수 묶음). 애매 꼴 문턱(0.5~0.8)은 D 에 안 둔다 — 보여 주기만 하는 통이라 확실한 것만.
- 가짜 judge 시험(8절) 에 `probs.D` 줄을 더해 「정리 필요 구역 · tidy 배열 · B 와 D 둘 다 0.5~0.8 이면 애매 한 곳만」 · 「하네스가 kind 를 모를 때 support 로 되돌아감 + 꼬리줄」 을 본다.

### 14-10. 통과선 · 접는 조건

- 통과선은 7절 그대로 : **합성 30 재현율 ≥ 0.9 (`B ≥ 0.5`) · 실제 50 오탐 ≤ 10% (`B ≥ 0.8` 중 want ∉ {B, D}) · 전체 한 번 ≤ 5분.** 판정은 **conflict 판**으로 한다. 「정리 권고 N 중 맞음 M · D 놓침 K」 는 적기만 하고 통과선에 안 넣는다.
- **3차 뒤에도 미달이면 `--pairs-only` 를 기본으로 접는다** (7절 「두 번 손질해도 안 되면」 을 세 번째까지 늘린 것 — 2차 때 「힌트 설계 문제라 3차는 작다」 로 한 번 더 둔 것이고, 이번이 마지막). 접을 때 판정은 `--judge` 옵션으로만 돈다.
- 재현율이 0.9 에 못 미쳐도 **D 권고 정확도와 support↔conflict 눈금 차이는 실측 문서에 남긴다** — 접더라도 다음 판(SemIf 다른 모델 · 라벨 늘림)의 재료다.

### 14-11. 걱정 · 못 정한 것

1. **글자 넷이 top-20 로그프롭에 늘 드나** — 안 재 봤다. `D` 가 빠지면 `probs.D` 가 없어 0 으로 읽히고 정리 필요가 조용히 0 건이 된다. 재측정에서 `D` 키 빠진 줄 수를 세고, 0 이 아니면 `readChoice` 쪽 문제로 적는다.
2. **D 라벨 3 건으로 권고 정확도를 재는 건 눈금이 거칠다** (M 은 0~3). 3차는 「D 가 뜨긴 하나」 만 보고, D 셋을 늘리는 건 다음 판 몫이다.
3. 낱말 차이 상한 `min(4, Overlap)` 의 4 는 숫자 상한과 맞춘 값이지 잰 값이 아니다. `hint_avg_runes` 로 2차와 견줘 글이 1.3 배 넘게 길어지면 3 으로 낮춘다.
4. support 되돌림(`kindFallback`)은 **종료 1 + 특정 글**을 보고 가른다 — 하네스가 다른 까닭으로 종료 1 이면 헛되이 한 번 더 돈다(시간 ×2). 「`--kind 는`」 글이 stderr 마지막 줄에 있을 때만 되돌리는 것으로 좁힌다.
5. 7절 ② 라벨 작업자가 D 를 「같은 규칙 다른 말」 로 좁게 쓰는지 — 라벨 기준 글 한 줄을 측정 셋 폴더 README 에 두는 건 git 밖이라 이 문서엔 못 적는다. 4차 라벨 늘릴 때 같이 정한다.
