# 아트 작업에서 lint 를 쓴 피드백 (2026-09-20)

> 반영 (2026-09-21) : `stage lint --changed` 를 넣었다. git 변경분(작업 트리 + 스테이지)을 툴이 스스로 모은다.

이 툴을 쓰는 게임 저장소에서 캐릭터 그림·점프 애니를 서브에이전트 4판으로 만들고, 판마다 `stage lint` 로 뒷검사를 한 기록이다.

## 결론

- `stage lint <파일…>` 은 **하네스·서브에이전트 뒤 검사기로 쓰기 좋다.** 그대로 두면 된다.
- 다만 **고친 파일 목록을 사람이 모아 넘겨야** 해서 빠뜨릴 여지가 남는다.

## 잘 된 것

| 무엇 | 왜 좋았나 |
| --- | --- |
| 섞인 확장자를 한 번에 받는다 | `.cs` · `.json` · `.prefab` · `.md` 를 섞어 8개씩 넘겨도 빠르다 |
| 종료 코드가 분명하다 | 0/2 뿐이라 `--bare` 하네스 판이나 서브에이전트가 끝난 뒤 자동 검사로 걸기 쉬웠다 |

## 막히거나 헷갈린 것

| 무엇 | 자세히 | 제안 |
| --- | --- | --- |
| 고친 파일 목록을 손으로 모아야 한다 | 서브에이전트·하네스 판은 훅을 안 타서, 메인 세션이 매 판마다 고친 파일을 모아 lint 를 직접 돌린다. 판이 4개면 목록을 빠뜨릴 여지가 그만큼 늘어난다. `stage lint -help` 에는 `-hook` · `-root` 뿐이고 변경분을 스스로 모으는 옵션이 없다 (2026-09-20 확인) | `stage lint --changed` 처럼 **git 변경분(작업 트리 + 스테이지)을 스스로 모아 검사하는 꼴**을 넣는다. 목록 빠뜨림이 없어진다 |
