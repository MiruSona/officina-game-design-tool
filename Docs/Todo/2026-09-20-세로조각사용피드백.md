# 세로 조각 사용 피드백 (2026-09-20)

> 반영 (2026-09-21) : Stop 훅 알림을 **세션당 한 번**(내용이 바뀌면 다시)으로 줄이고, 할 일마다 「무엇을 하면 사라지나」를 붙였다. `--help` 종료 0 은 이미 고쳐져 있었다.

한 게임 저장소에서 하루 동안 `stage` 를 쓴 기록이다.
8단계 「세로 조각」에서 물음 5개가 다 통과이고, 판정(플레이 기록)은 사용자가 일부러 미뤄 둔 상태였다.

## 막힌 것

- 없다.

## 헷갈린 것

| 무엇 | 자세히 | 제안 |
| --- | --- | --- |
| Stop 훅 알림이 되풀이된다 | `stage done --hook` 이 「판 끝 할 일이 남았습니다 : 플레이 기록 한 편 · 기억 1건 (결정과 공수 눈금)」을 **AI 가 멈출 때마다** 띄운다. 사용자가 「Stop says 가 자꾸 뜨는데 저게 뭐냐」고 물었다. 판정을 일부러 미뤄 둔 동안에는 같은 말이 대화 내내 나온다 | 아래 「바라는 것」 |
| `stage done --help` 가 오류처럼 끝난다 | 사용법을 찍고도 마지막 줄이 「옵션이 잘못됐습니다 (stage done)」다. 도움말을 청했는데 잘못 친 것처럼 보인다 | `--help` 는 사용법만 찍고 종료 0 으로 끝낸다 |

## 잘 된 것

| 무엇 | 왜 좋았나 |
| --- | --- |
| 세션 시작 훅의 `stage show` | 단계 · 판 · 물음 통과 수를 바로 알려 줘 현황 파악이 빨랐다 |
| `stage lint <파일>` 의 종료 코드 | 0 / 2 가 분명해 서브에이전트에게 검사를 맡기기 좋았다. 이날 `.cs` 17개 묶음과 md 1개에서 0 이 나왔다 |

## 바라는 것

- Stop 훅 알림은 **세션당 한 번**, 또는 **내용이 바뀔 때만** 띄운다.
- 아니면 알림 끝에 「무엇을 하면 사라지나」(어느 명령 · 어느 파일)를 한 줄 붙인다.
