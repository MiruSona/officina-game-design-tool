# GamedesignTool 할 일

> 공수 눈금은 **의견**이다 — 실측하면 고친다.
> **툴 전체에 3일을 넘겨 쓰지 않는다.** 넘어가면 설계가 큰 것이니 멈추고 다시 본다.

## 1판 — 관문 CLI + 상태 탭 (반나절)

| 순 | 부품 | 무엇을 하나 | 공수(의견) |
| --- | --- | --- | --- |
| ① | **상태 파일 모양** | 단계 · 판 번호 · 되돌아간 기록 · 물음 배열(물음 / 상태 / 기준). 30줄쯤 | 30분 |
| ② | **단계 정의 기본값 + 덮어쓰기** | 툴이 9단계 기본값을 갖고, 붙은 저장소의 설정 파일이 있으면 그것으로 덮는다 | 30분 |
| ③ | **`stage show` · `next` · `back` · `check`** | 상태 파일을 읽고 쓴다. `back` 은 되돌아간 까닭을 같이 남긴다 | 1~2시간 |
| ④ | **`stage lint` + 훅 셋** | 순서·모양 검사. `SessionStart` · `PreToolUse` · `Stop` 에 건다 | 1~2시간 |
| ⑤ | **`dash` 상태 탭** | 정적 HTML 한 장. 스테퍼 · 지표 타일 3개 · 기둥 상자 · 문서 체크 · 고리 상태도 | 1~2시간 |

**1판 합계 눈금 반나절.** 여기까지면 「지금 몇 단계인지」가 지켜지고 눈에 보인다.

- ①이 어긋나면 뒤가 다 어긋난다. **먼저 못 박는다.**
- ④의 검사는 **셀 수 있는 것만** 본다. 판단이 섞이는 것은 넣지 않는다.
- 프로토타입 폴더는 ④의 검사에서 **뺀다.**

## 2판 — 프로토타입 갤러리 탭

| 순 | 부품 | 무엇을 하나 | 공수(의견) |
| --- | --- | --- | --- |
| ⑥ | 갤러리 탭 | 열 4개 칸반(만드는 중 · 확인 대기 · 통과 · 불통). 카드에 물음 한 줄 + 기준 개수 | 2~3시간 |
| ⑦ | meta 읽기 | 프로토타입 폴더의 meta 덩이를 훑어 카드 재료로 만든다. **읽기만 한다** | 1~2시간 |

- 프로토타입을 만드는 툴과는 **코드로 묶지 않는다.** 형식이 바뀌면 문서로 맞춘다.
- 프로토타입이 2개 이상 쌓인 뒤에 만든다. 하나뿐이면 갤러리가 필요 없다.

## 나중 — 밸런스 탭

| 순 | 부품 | 무엇을 하나 | 공수(의견) |
| --- | --- | --- | --- |
| ⑧ | 수치 데이터 읽기 · 스키마 검사 | JSON 여러 개(종류별로 쪼갬). 커밋 전에 오타·빠진 칸을 잡는다 | 반나절 |
| ⑨ | 곡선 그래프 + 식 보여 주기 | 값을 다 적지 말고 「식 + 검산용 몇 점」. 식을 글자 그대로 보여 주고 옆에 곡선 | 반나절 |
| ⑩ | **읽기 전용 미리보기 슬라이더** | 브라우저 안에서만 값을 흔들어 곡선이 어떻게 움직이나 본다. 파일은 안 건드린다 | 2~3시간 |
| ⑪ | N일 자동 플레이 시뮬 | 표만 봐서는 안 보이는 「고이는 자원 · 막히는 구간」을 찾는다 | 반나절 |

- **실제 수치가 생기기 전에는 안 만든다.** 세로 조각 단계에서 수치표를 쓸 때가 시작점이다.
  그 전에는 만들 데이터가 없어 상상으로 만들게 되고, 상상으로 만든 툴은 다 틀린다.
- ⑩은 **꼭 넣는다.** 스프레드시트를 버리며 잃는 것의 대부분을 이 하나가 메운다.
- 웹에서 **고치기까지** 만들면 공수가 세 배로 뛴다(2.5일 → 6~8일). 「보기만」으로 시작한다.
