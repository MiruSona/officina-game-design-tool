# 9단계 뒤 반복 제안 (2026-10-03)

한 게임 저장소에서 9단계 「확장」까지 `stage` 를 써 본 기록이다.
Unity 세로 조각이 끝나고 WebGL 판을 남에게 돌리는 단계에서 나온 피드백이다.

## 결론

- **세로 조각 판정이 전부 통과한 뒤부터는 물음 · 기준 · 판정 절차가 맞지 않았다.**
  물음 정하기 · 기준 숫자 · 수치 확정이 「게임을 좋게」가 아니라 「절차 채우기」가 됐다.
- 그래서 사용자가 2026-10-03 에 9단계 뒤를 **「놀기 → 피드백 → 고치기 → 새 판」 반복**으로 바꿨다.
- 절차 정본 `Docs/Guide/기획절차.md` 의 「### 9. 확장」 뒤에 한 절을 더하자는 제안이다.
  「## 되풀이 규칙」의 「한 판」 표(판 끝에 하는 것 셋)와 「새 아이디어가 들어왔을 때」 관문도 같이 손본다.

## 제안 — 「### 10. 반복」 (이름은 제안)

| 무엇 | 내용 |
| --- | --- |
| ① 반복 1회 | 놀기 → 고치기 → 새 판. **판 번호가 곧 반복 번호**다 |
| ② 반복마다 남기는 것 | 기록 파일 하나(피드백은 사용자 말 그대로 · 결정 · 고친 것 · 미룬 것 · 넘긴 것) + 기억 1건 |
| ③ 새 시스템이 나오면 | 「3단계로 돌아간다」 대신 **Won't 표에 대 보고 사용자가 그 자리에서 정한다** |

- ③ 의 까닭 : 9단계 함정 문장 「3단계로 돌아갈 일이다」가 작은 추가(예 : 방치 중 자동으로 다음날 넘기기)에도 걸려 너무 무거웠다.
- **끝 기준은 미리 안 정한다.** 사용자가 「됐다」 할 때 그 모양을 보고 적는다. 「해 보고 고칠 기본값」 표 후보다.

## 멈춘 것

- `stage ask` · `stage check` · 판정 기준 숫자. 훅은 그대로 둔다 — lint 가 잡은 것은 대부분 실수였다.
- 막히면 그때 푼다. 그래서 **「반복 단계」에서 lint 가 무엇을 봐야 하나**는 열린 물음으로 남긴다.

## 잘 된 것

- 컨셉이 맞나를 싸게 확인하는 1~8단계는 잘 맞았다. HTML 프로토 셋과 세로 조각 판정으로 코어루프를 두 번 고쳤다.
