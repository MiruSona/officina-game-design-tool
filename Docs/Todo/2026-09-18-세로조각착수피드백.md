# 세로 조각 착수 때 stage 피드백 (2026-09-18)

> 반영 (2026-09-21) : `back` 을 앞 단계면 어디든 허용 · L2 문구에 푸는 법 추가 · 하위 폴더 규약과 「훅 없는 판은 lint 직접」을 README·스킬에. 「있는 03-시스템 문서 목록 찍기」는 그 목록이 늘 비어 안 만들었다.

한 게임 저장소에서 9단계로 넘어갔다가 8단계 「세로 조각」으로 되돌아가고, Unity 코드를 쓰기 시작하면서 `stage` 를 쓴 기록이다.

## 막히거나 헷갈린 것

| 무엇 | 자세히 | 제안 |
| --- | --- | --- |
| `stage back 8` 이 거절된다 | 되돌아가는 조건이 3 · 4 · 5 단계로 못 박혀 있어 9 → 8 은 안 된다. 「8단계를 안 하고 9로 넘어갔다」는 경우가 실제로 났고, 결국 `Docs/Todo/기획상태.json` 을 손으로 고쳤다 (되돌아간기록 항목도 손으로 더함) | `back` 이 임의 단계를 받되 `--why` 를 필수로 하거나, 최소한 「바로 앞 단계」는 허용한다. 손으로 고친 뒤 `stage show` 가 정상으로 읽힌 것은 확인했다 |
| L3 가 `Docs/Design` 바로 아래 날짜 이름을 막는다 | 세로 조각 설계는 기획서(번호 이름)도 조사(날짜 이름)도 아니라 자리가 애매했다. 하위 폴더 `Docs/Design/세로조각/` 에 두니 L3 가 안 본다 | 하위 폴더는 검사 밖이라고 문서에 한 줄 적거나, 「설계 문서는 하위 폴더에」를 규약으로 정한다 |
| L2 가 코드 폴더를 볼 때 `03-시스템-*.md` 유무만 본다 | 어느 시스템 문서가 필요한지는 안 알려 준다. 첫 코드는 농장이라 `03-시스템-농장.md` 를 먼저 썼는데, 훅 메시지만으로는 무엇을 써야 하는지 몰랐다 | 막을 때 「지금 있는 03-시스템 문서 목록」을 같이 찍는다 |
| 하네스 판(`--bare`)은 lint 훅을 안 탄다 | 로컬 모델이 코드 폴더에 새 파일을 써도 L2 가 안 돈다. 메인 세션이 판이 끝난 뒤 `stage lint <파일…>` 을 직접 쳐야 한다 | README 에 「훅 없이 쓸 때는 끝에 lint 를 직접」 한 줄 |

## 잘 된 것

| 무엇 | 왜 좋았나 |
| --- | --- |
| 세션 시작 훅의 `show` 요약 | 문맥이 잘려 다시 시작해도 「8단계 · 물음 5개 통과」가 맨 위에 와서 바로 이어 갔다 |
| `lint` 가 쓰기를 막는 것 | 날짜 이름 문서를 `Docs/Design` 에 두려다 막혀서 자리를 다시 생각했다. 규칙 문서보다 확실했다 |
